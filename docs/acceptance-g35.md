# G35：容器内核调用与取消清理

2026-10-31。实现单卡任务的完整内核调用组件，包括准备、源码发送门槛、可信答案比较、批次协议、独立正确内核恢复与原记录清理。按当前授权，本次**不查询、映射或使用真实 GPU**；真实运行使用独立无设备服务与固定 CPU guest。设计见 [ADR-051](adr/051-container-kernel-execution.md)、[RFC-021](rfcs/021-gpu-container-supervision.md)，操作统一在[无设备调用链检查](deployment/gpu.md#container-kernel-flow)。

## 结果与范围

- **十次真实 CPU/runsc 调用通过**：正常 Run、正常 Submit、错解、编译错误、运行错误、独立恢复失败、取消、非法请求、维护恢复和后续正常新调用。共享可信任务流程在实际私有通道及 runsc 中运行；guest 严格拒绝携带保护答案或隐藏名称的帧。报告为 `test-results/px-container-kernel-4e9d767839ba/result.json`，日志为 `g35-kernel-cpu-fixed.log`。
- **735 项组件检查通过，无跳过**：新调用者的准备身份、开始回调、原记录替换、完成帧拒绝、外层清理、最终空闲观察，以及共享协议、宿主调用兼容、资源、旧记录、控制器、凭证和发布边界。日志为 `g35-components-final.log`，JUnit 为 `g35-components-final.xml`。此前 183、237、30、693 和 103 项定向结果为重叠范围，不累加。
- **217 项实际 PostgreSQL 检查通过，无跳过**：启动、领取与结算、预约、凭证发布、健康准入、私有成绩、worker 和持久容器恢复。记录为 `g35-postgres.log`、`.xml`；一次性数据库容器与卷已由原入口核对移除。
- **原控制器七组真实 CPU 检查通过**：UID 映射、双向锁竞争、错误用户与挂载拒绝，以及容器到容器、容器到宿主、宿主到容器的原记录接管。报告为 `px-container-controller-66863e01942f/result.json`，日志为 `g35-controller-cpu.log`；未启用设备观察或设备映射。

收尾只读审计 `g35-audit.json` 确认两轮内核验收及控制器验收的 32 个自有容器、4 个镜像标签和 20 组原进程身份均已清理，临时存储已移除。最终两份通过报告的源码摘要与当前文件一致；原失败报告保持其原始身份。既有 Web、WASI worker、CPU 辅导服务均健康，本轮未重启它们。Ruff 检查与 622 文件格式检查通过；文档修改后 36 项发布检查和九份文档的 374 个本地链接检查通过。

真实 CPU guest 使用固定向量程序，源码只作为数据，不编译或执行；错误模式由可信验收入口固定选择。CPU 的编译完成帧与计时字段只证明协议和控制器处理，不是 CUDA 编译、性能或设备恢复结果。GPU 专用 `KernelTask` 的观察器、设备准备与源码发送门槛由组件替身验证；物理单卡、完整 GPU 镜像调用和正式成绩链路尚未实测。

## 实际失败与修正

首次 CPU 镜像运行通过前六个场景，在取消场景发生内部清理中断，报告为 `px-container-kernel-e72e3c83aaf2/result.json`，日志为 `g35-kernel-cpu-initial.log`。通道断开会触发执行回调，而原 runsc 清理命令同样调用该回调；可信程序因此在收集报告前退出。原外层任务仍按 journal 停止并移除，现场副本与原失败保留，没有把退出本身算作通过。

修复保存创建时验证过的清理硬期限。清理调用不依赖已失效的通信或执行回调，只允许列出状态、核对原 guest、删除原 guest；不能启动任务、认领未知 ID 或延长期限。执行预算仍预留独立恢复与清理时间。随后重建固定镜像并完成上述十次调用，取消报告确认原 guest 停止且没有返回结果。

共享函数迁移时，首次组件检查发现旧模块缺少 `VECTOR_REFERENCE` 导出；已恢复兼容，原记录为 `g35-components-initial.log`。另一次清理测试命令引用了不存在的文件，未收集测试；更正为仓库实际资源测试后通过，记录为 `g35-cleanup-components.log` 与 `g35-cleanup-components-fixed.log`。这些准备/兼容错误与真实 CPU 取消故障分别保留。
