# 学习记录和社区维护

收藏、笔记、阅读标记和实践证据在“我的学习”中进入，均默认私有。笔记可以关联一个题目版本或知识节点。更新教程后，旧阅读标记保留但提示需要重新确认。阅读标记不计入路径练习通过比例。

社区允许讨论、提问、版本题解、博客、题目反馈和评论。作者先保存草稿，再选择“主动提交公开审核”；页面明确说明正文及用户名将公开。送审前请确认正文不含密钥、个人隐私或无权发布的材料。社区正文不会自动复制私人提交代码。公开内容修改后停止公开并重新审核；撤回与删除均由作者发起。

## 题目反馈

从题目页“反馈此题”进入，表单预选当前题目版本。报告错误时写明出错位置、可复现的公开示例、预期与实际表现；提出修订建议时说明改法和理由。反馈必须选择明确版本，旧版本仍可选择；题目更新不移动旧反馈。关联题目下线时，反馈及评论停止公开。

“题目反馈”入口可按题目和类型查看已公开反馈。审核队列的“待审题目反馈”筛出主动送审的记录。审核者可以公开或退回并说明原因；审核通过只表示反馈可以公开讨论。维护者可通过评论说明是否采纳及修订版本，实际题目更新仍走[内容贡献流程](content.md)。举报社区违规内容继续使用“私有举报”，举报原因只向举报人及审核者显示。

反馈沿用现有撤回、删除、账号导出和删除边界；不改变原提交结果、学习进度或题目正文。迁移 `community.0003_problem_feedback` 增加反馈类型和必须有版本的数据库约束，不增加表或运行角色权限。设计见 [RFC-014](rfcs/014-versioned-problem-feedback.md)。

## 分配审核权限

在可信管理环境、以数据库管理凭证运行以下命令。运行中的 Web/worker 不需要管理凭证。先核对目标账号，再授予或撤销直接权限：

```sh
python manage.py community_moderator REVIEWER_USERNAME --grant
python manage.py community_moderator REVIEWER_USERNAME --revoke
```

命令只改变 `community.moderate_content` 直接权限，不设置 staff/superuser，也不移除组继承权限。撤销后仍需核对账号是否通过组或超级用户身份拥有权限。避免将日常审核账号设为超级用户。账户不得审核自己的内容。

审核者登录后从社区“审核队列”处理待审正文、评论、举报和申诉。决定必须填写作者可见的说明。每次处理都绑定当前修订；遇到冲突时重新加载并阅读新内容。接受申诉只是重新送审，不能跳过正文审核。举报人的私密说明不会展示给被举报作者。

## 数据与升级

账户 JSON 导出包含本人的学习数据、社区文字及本人提交的举报/申诉，不包含他人的私密案件。删除账号或正文会级联删除相关内容；最小审核事件保留且删除账号时清除操作者关联。备份、日志及依法需要保留的数据应在站点自己的隐私政策中说明。

应用初始迁移新增 `learning_*` 与 `community_*` 表。发布工具按已应用迁移核对并授予 Web 表权限；worker 无权读取笔记或社区案件。升级保持已有题库，不自动用新版本的 starter 内容覆盖维护者的目录。新增内容须通过[内容贡献流程](content.md)校验、审核和显式导入。

本页描述当前软件行为。公开实例的投稿许可、举报处理时限、申诉渠道、数据保留和运营责任需由维护者另行确定。
