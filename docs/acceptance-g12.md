# G12：固定 CUDA 启动检查的协议与中断边界

日期：2026-10-31。设计：[RFC-019](rfcs/019-gpu-kernel-evaluation.md#正式就绪检查)、[ADR-028](adr/028-gpu-startup-kernel-checks.md)。遵循维护者“先继续不占 GPU 的开发”的范围。

## 实现与本次结果

十九项固定 CUDA 用例已接入维护适配器和私有控制器。请求只接受用例名与随机挑战，复用正式交互执行、控制器比较和独立正确解恢复；清理或恢复失败不返回成功检查。固定用例与限制见 ADR，操作入口继续集中在 [GPU 指南](deployment/gpu.md)。

- `test-results/g12-kernel-initial.xml`：首轮 136 项通过，无跳过。
- `test-results/g12-kernel-final.xml`：240 项通过，无跳过，覆盖固定用例、报告拒绝、控制器、适配器、会话、契约、既有探针、运行环境及资源检查。两项中断测试使用实际固定 CPU 管道进程；程序只发预定协议帧并休眠，绝不编译或执行收到的 CUDA 源码，也不证明实际容器或 GPU 清理。
- `test-results/px-gpu-controller-ea05e805a8f3/result.json`：实际 RootlessKit 控制器加载、认证连接、准备前拒绝和自然退出通过；自有服务、工作目录及临时根已清理。未准备 Podman/CUDA 或访问 GPU。
- 全仓 Ruff 检查和 454 个 Python 文件的格式检查通过。CPU 策略摘要保持 `ae5cfea16ee6c6fa5cc76b5a8356fc3e30c27bfe8a86de27c8456ca55c2111c8`；GPU 执行摘要为 `69496ee8cf35e4ffe70c17929be40c00ed84edc7c34e836642802d78b363fd53`。

拒绝场景包括请求夹带源码、非维护服务、未知用例、旧挑战、错误 verdict、缺失编译、零性能样本、Run 夹带性能、隐藏测试名称、宿主 OOM 代替设备内存不足、错误容器身份、清理/恢复失败，以及未触发中断时发生的任意平台异常。

本次没有测试失败。验证没有改变现有数据库、用户站点、设备预约、主机服务或共享运行时配置；没有生成运行凭证。README 的用户可用能力仍准确，未增加尚未交付的启动命令。

## 尚未完成

新的十九项用例尚未在 GPU 上运行。G1/G2 的旧硬件记录不能替代本次执行路径的正确性、性能、恢复和总时限验收。整控制器退出、控制通道失联及独立服务期限仍需接入完整启动检查；凭证、worker、正式题型与产品闭环继续待完成。此增量不把设备置为 ready。
