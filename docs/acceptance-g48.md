# G48：GPU 发布就绪观察与冻结环境核对

日期：2026-11-01。对应 PRD R-09、R-16；[设计](rfcs/022-gpu-release-coordination.md)、[决策](adr/064-gpu-release-readiness-observation.md)、[集中检查入口](deployment/container-gpu-worker.md#readiness-observation)。本轮未调用实际 Docker、加载镜像、查询或映射 GPU，也未更改现有运行服务。

## 实现与验证边界

协调器内部新增就绪观察，要求原运行容器、启动实例、完整配置、本代 worker 与新鲜设备心跳同时匹配。每次数据库快照用单条只读 SQL 观察暂停归属、目标设备、全部待执行任务及所有物理预约；其他设备或已删除任务留下的预约也不能忽略。观察不持设备/队列行锁等待启动，不修改任务、预约、设备状态或私有 receipt。

完整环境使用既有版本校验器，并与原节点、实际 daemon 和冻结制品核对。发布包完整校验后再次检查归档源码；固定运行时范围、runsc、NVRTC、Docker CLI 声明仅从 AST 字面量读取，不导入或执行归档 Python，不借用当前工作树来计算旧包契约。环境检查后复查原实例和心跳，再取最终快照；变化的所有者、环境、任务或预约不能沿用先前结果。成功不持久缓存为曝光凭据，等待从原容器启动时间计时，超时不重启或清理对象。

最终相关回归 **728 passed、6 skipped**，见 `test-results/g48-components.xml/.log`。六项实际 PostgreSQL 专项在当前 SQLite 环境中跳过，不计入通过；包含新增的只读事务、不阻塞 worker 心跳及其他设备孤立预约检查。真实 Docker/数据库/设备状态在组件测试中均由显式模型提供，结果不证明实际 GPU 就绪或部署成功。

## 关键结果

- 真实私有配置、文件锁和临时源码归档与模型化 Docker/数据库共同验证：缺失/隔离/预约设备、旧 worker/启动、过期或未来心跳、未完成队列、孤立预约、原暂停或维护条件丢失均不能通过。持有原设备锁的模型 worker 不会被观察者阻塞。
- 固定任务/控制器/运行时契约、镜像、驱动、管理清单、runsc、NVRTC、Docker CLI、daemon、设备和执行策略逐项错配被拒绝。源码篡改、非字面量声明、重复声明、不完整范围与错误任务摘要不会借工作树补全，含执行调用的声明未执行。
- `test-results/g48-boundary-regression.xml/.log` 保留 **2 failed、1 passed**：环境核验期间容器退出或心跳过期仍被接受。修复后重复核对实例、累计读取耗时，并重新取得最终数据库快照。最终快照的所有者/环境变化、隔离、预约和新待执行任务另有回归。
- 等待测试使用显式时钟，验证覆盖完整启动预算、超时保留对象、重试不续期，以及同一实例稍后通过；没有实际等待一轮 GPU 启动。两次观察会重新读取，旧成功不会缓存。

早期 `g48-readiness-before`、`g48-boundary-before` 记录了测试夹具的两处错误：试图改写同一不可变发布代，以及未显式发布新代；生产拒绝均符合预期。随后 `g48-core` 的 56 passed、6 skipped、1 failed 是模型环境与冻结清单共享对象导致的夹具错误；改为独立副本后最终回归通过。中间结果与最终结果重叠，不累计为独立检查数。

旧制品只读检查通过，见 `test-results/g48-old-archives.json`：F 清单摘要 `896e1c1b605025376ed30786ea4e79d3fde008c97e7d114bf91febd86cc62482` 的 464 个源码文件、两个镜像；G42 清单摘要 `44b6ca03b1e22d92382e5a04b578dee64813f57eceb1b3c3485117b0fdfa2142` 的 839 个源码文件、四个镜像及完整层。`test-results/g48-frozen-runtime.json` 保存实际从 G42 归档推导的固定契约；没有导入镜像或执行归档代码。

源码身份记录在 `test-results/g48-policy-identity.json`。CPU 策略和 GPU execution/controller 源码与父提交 `5895249` 相同；数据库辅助代码变化会改变 worker 源码契约，实际使用需要匹配的新制品。静态和格式检查通过，部署操作继续集中维护。

## 未完成事项

实际 PostgreSQL、Docker 镜像入口/生命周期以及完整 GPU 启动、队列、清理、升级回滚和曝光恢复仍待验收；本轮新增内部观察不解除 `apply` 的 GPU 拒绝，也不发布正式 CUDA 内容。

此前旧测试镜像恢复被自动审批拒绝，相关许可仍未收到；本轮未重试加载或启动测试数据库，[G44](acceptance-g44.md) 的真实 Web 恢复及完整 CPU 发布复验继续保留。托管 CI/runner、长期部署目标和公开运营/授权事项仍按[需求追踪](requirements.md)推进。
