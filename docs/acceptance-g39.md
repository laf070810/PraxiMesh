# G39：容器控制器故障与新实例恢复

2026-10-31。将三种固定控制器故障接入容器维护任务，故障前验证正确程序，故障后按原实例清理并在新容器中正确恢复。设计见 [ADR-055](adr/055-container-controller-faults.md)、[RFC-021](rfcs/021-gpu-container-supervision.md)；操作集中在[无设备控制器故障检查](deployment/gpu.md#container-controller-faults)。本轮不查询、映射或占用 GPU。

## 实现边界

宿主和容器共用固定名称、挑战与触发握手，保留各自的监督和身份报告。容器报告严格绑定原 ID、启动 nonce、实际硬期限、断连时刻和原 journal 归档。故障观察器只观察独立退出；通信断开须先确认原实例仍活跃，再按原记录停止。异常退出必须是监督器的 70，独立超时必须是 124，不能用任意断连、OOM 或主动停止替代。

故障对象是任务容器内的可信执行进程，独立 PID-1 监督器继续承担期限。持有 Docker socket 的控制容器接管沿用另一组实际检查；本轮没有将任务进程退出外推为完整常驻 worker 的退出/接管验收。

只有固定正确程序比较通过、原 guest 和附着进程仍活跃时才允许触发故障。原任务清理和空闲观察完成后，适配器在同一锁、任务和预约下创建新的维护对象，容器 ID 与 nonce 都须不同。新恢复、原归档或环境复核失败均扣留报告。总维护预算保留最多 90 秒故障及 90 秒独立恢复；实际 PID-1 期限没有延长。

## 真实 CPU 验收

最终五组场景、十五个自有任务实例通过，报告为 `test-results/px-container-lifecycle-27ec04bc04a7/result.json`，日志为 `g39-lifecycle-final.log`。每个故障都在活跃 guest 已准备后记录完整原进程树；独立退出/超时在任何 journal 主动清理前确认该树消失。每组都经过新的正确维护恢复或预期的恢复失败，并以新的普通 Run 返回 `accepted` 结束。

| 场景 | 实际观察与后续行为 |
| --- | --- |
| 控制器退出 | 约 3.589 秒断连；原 PID 为 0、退出码 70，主动清理前原进程树已消失；新恢复和普通 Run 通过 |
| 通信断开 | 约 3.611 秒断连，原容器仍运行；按原 journal 清理后，新恢复和普通 Run 通过 |
| 独立硬期限 | 硬期限 40 秒，约 40.008 秒观察到断连；退出码 124，主动清理前原进程树已消失；新恢复和普通 Run 通过 |
| 准备程序错误 | 固定数值比较失败，故障未准备、不返回通过报告；清理后新恢复和普通 Run 通过 |
| 后续恢复错误 | 故障实例独立退出并清理，新恢复的数值比较失败；成功报告被扣留，随后新的普通 Run 通过 |

CPU 专项的故障总预算为 45 秒，包括原 5 秒停止余量；上述时间不是 GPU 性能或真实 CUDA 启动预算验收。CPU guest 只计算固定向量，收到的源码是协议数据，不编译、导入或执行学员代码，也不加载 CUDA。

首轮 `px-container-lifecycle-9f1104b6a5b5/result.json` 的五组场景也通过，日志为 `g39-lifecycle-first.log`；它在 journal 清理后核对进程树，并以新的维护恢复结束。后续加强了主动清理前的独立消失证据，以及维护后回到普通 Run 的验证，得到上面的最终报告。保留两轮各自的入口源码摘要，不将较早范围冒充后续验证。

## 回归与收尾

**1,199 项相关回归通过，无跳过**，记录为 `g39-components.log`、`.xml`。覆盖新握手、正确性准备、提前断连/错误状态/实例替换/OOM 拒绝、原归档匹配、恢复预算、新对象顺序与失败扣留，以及既有宿主、准入、worker、历史和发布边界。早期 170 项既有检查、74 项协议专项和 154 项组合检查分别保留在 `g39-existing-first`、`g39-fault-protocol`、`g39-fault-components` 的日志和 JUnit 中；范围重叠，不累加为独立测试数。

**原十八项真实 CPU/runsc 调用与资源场景通过**，报告为 `px-container-kernel-8cade9a80b72/result.json`，日志为 `g39-kernel-regression.log`。包括正确/错误程序、Run/Submit、取消、命名内核检查、九项资源检查、恢复失败及新调用；这些仍是固定 CPU 证据，不是 CUDA 或正式成绩。

**无设备控制镜像七项实际检查通过**，报告为 `px-container-controller-ed1f58b82231/result.json`，日志为 `g39-controller-final.log`。覆盖共同锁与用户映射、错误用户、替换锁目录/socket，以及容器间、容器到宿主、宿主到容器的接管；镜像内完整执行策略与当前源码相符。没有启用 NVIDIA 管理观察。

收尾核对 `g39-audit.json` 确认上述四份报告涉及的 **63 个自有容器、5 个镜像标签和 51 组原进程记录均已清理**，临时存储已删除。最终三份报告的逐文件源码摘要一致；首轮故障报告只保留其较早验收入口的差异。原有 Web、worker 与 tutor 均保持运行且健康，没有重启或改写。
