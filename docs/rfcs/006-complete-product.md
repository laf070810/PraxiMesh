# RFC-006：阶段 B/C 的完整产品实施

状态：实施中。2026-10-23。依据：[PRD](../../PRD.md)及维护者新增目标“把所有内容全部实现”。阶段 A 是已验证的基线，不是本轮完成边界。

## 范围与分批实施

全部 R-01–18、AC-01–08 以及 PRD 的安全、隐私、贡献、部署和运维要求进入[需求追踪表](../requirements.md)。先后顺序用于控制变更和验证成本，不删除后续目标。PRD 中非穷举的领域/语言举例采用可扩展模型和有代表性的可用内容来验收；专业评测必须实际执行相应任务，不能仅靠标签或适配器接口认定完成。

1. B1：扩充高质量题库和路径；私有收藏、笔记、教程阅读状态；按领域/概念汇总实践证据和复习建议；讨论、题解、举报、审核及申诉基础。
2. B2：中英界面与版本化内容翻译；自愿公开主页/作品和可比较榜单；多阶段 CPU 项目、本地公开测试/提交工具；第二种语言和第二种评测形态真实验收。
3. C1：科学计算、ML、Agent 和 GPU 专业评测，独立资源策略、指标、版本/硬件可比性和资源额度；逐类真实隔离及正确/错误程序验收。
4. C2：博客、组织课程与角色、第三方题库的命名空间/来源/审核/撤回；分层提示、可选 AI 辅导、个性化路径与有边界的能力分析。
5. 全范围回归、目标环境部署及 PRD §13 的维护者决定。缺少真实硬件、外部服务、公开许可或部署目标时记录待办，继续其他独立实现，不用模拟结果消除缺口。

## 应用和数据边界

保留 Django、服务器模板、关系数据库和独立评测器。新增 `learning` 与 `community` 应用，复用 core 的稳定知识 ID、不可变题目版本及用户。相比继续扩大 core.views，独立应用更便于权限测试；相比拆网络服务，无需增加分布式事务和运维负担。

学习记录默认私有。收藏绑定稳定题目，笔记保留所关联题目版本；阅读标记是用户自述，不等于掌握。实践证据只来自本人的真实正式提交，区分公开 Run、平台错误、旧题版本与当前通过。建议必须说明依据；不会把一次 Accepted 显示为掌握百分比。

社区文字按纯文本保存、转义显示，不执行或直接渲染投稿 HTML。题解绑定明确的题目版本，默认草稿，作者明确提交公开后进入审核；只有审核通过的记录可以公开读取。评论同样经过审核；作者可撤回/删除。举报和申诉只向本人及具备权限的审核者开放，审核行为留存最小审计记录。发布限流、长度上限、CSRF、分页、隐藏内容的跨账号访问及删除级联必须测试。正式公开运营的治理条款仍由维护者确认，不以实现审核工作流代替政策批准。

排行榜必须由明确的同一挑战、版本/策略和可比指标构成，用户自愿加入；私有提交不会因新增社区页面自动公开。账号导出和删除同步覆盖新数据，最小数据库授权和备份/恢复核对同步覆盖新表。

## 内容与执行扩展

内容扩充保留现有身份和版本。新题必须有独立题意、边界、参考解、错误变体和真实隔离测试；保留现有路径，新增目标明确的路径。新增运行方式使用版本化 evaluator，并声明其能力/资源契约；生产 worker 仅运行当前已验证策略，不提供宿主解释器回退。

中英翻译需区分界面语言与内容语言，保留稳定 ID，缺少译文时明确回退。第三方内容导入在后续独立 RFC 明确命名空间和包级发布范围，避免当前全包替换语义误撤回其他机构内容。

GPU、原生扩展和外部模型服务会引入不同信任/成本边界，实施前分别记录方案与环境核验。不能把 CPU 函数题、规则提示或假响应当成 GPU/ML/Agent/AI 服务已完成。

## 迁移与验证

新增应用使用迁移和外键；不改写历史 core 迁移。备份恢复、角色授权、账号导出/删除、发布源码白名单和镜像 COPY 范围一起更新。任何新表都会使旧版恢复/权限假设失效，必须在 PostgreSQL 和真实容器重新验证。

每批先跑有意义的权限/状态转换/数据保留测试，再做浏览器和实际执行验证。全目标完成必须逐项查看需求追踪表对应的当前证据，阶段报告不得将本批完成等同于整个目标完成。
