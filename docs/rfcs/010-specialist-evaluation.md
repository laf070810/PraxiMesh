# RFC-010：共用可信边界的 CPU 专业评测

状态：已实现，C 本地联合验收通过，具体边界见 [C 验收](../acceptance-c.md)。细化 RFC-006 的 R-16；真实 GPU 主机验收按维护者决定后续处理。

## 选择与边界

ML、科学计算和 Agent 复用版本化题目、私有源码、队列租约、WASI 隔离、正式提交、学习进度和本地公开测试。它们各自使用固定的可信评测契约，内容包不能上传 checker、修改资源政策或选择新的运行时。参考实现与学习者实现均在同一受限环境执行。

第一批专业实践采用 CPU 上可完整验证的小任务，不要求网络、外部模型或 Python 原生扩展。ML 学习者提交 `train(features, targets)`，只得到训练数据，返回有界的权重与偏置；宿主在独立留出数据上计算 MSE/MAE。科学计算提交 `fit(x, y, sigma)`，返回直线参数和协方差；宿主用独立加权拟合基准检查参数、协方差与正规方程残差。χ²/自由度只描述模型对数据的适配，不直接等同实现正确性。

Agent 提交 `act(observation, state)`。宿主提供明确列出的账本工具，验证每次工具名与参数、是否真的读取了必要记录，并计算最后报告的整数金额与数量。轨迹、状态、调用次数、输出和时间均有上限；任意网络工具、宿主文件、额外进程或直接提交“成功分数”均不被授权。详见 [Agent 契约](../agent-contract.md)。

## 统一资源预约

`cpu-invocations-v1` 是固定调用上限的记账政策，不是已用 CPU 秒或收费账单。默认每账号每日 120 单位，以 UTC 日期归属；函数/ML/科学场景每个测试预留 1，完整程序预留 2，Agent 每个 episode 预留最多 6，最多 8 episodes。

入口和配额共用事务锁。正式任务与 Run 都先预约，幂等重放不会再预约；worker 取得有效租约并即将启动第一段用户代码时才消费。只有在尚未执行前被可信平台失败终止才释放预约，未知结果或已执行任务不返还。过期 worker 不能消费、完成或释放其他租约的任务。既有历史提交迁移为零单位 `legacy`，不追溯扣额。Agent 每轮前续租并检测取消，不能在任务已删除后继续开启下一轮。

## 成绩与能力证据

`verified_evidence` 只接受与题目版本、语言、评测器、运行环境指纹、预约状态和结果结构一致的正式记录。专业反馈只公开允许字段，隐藏场景不返回数据、参考模型或轨迹。Agent 公开轨迹还需按该版本的公开账本重放校验，防止伪造工具结果。学习、项目、组织课程和智能学习证据共同使用这一入口。

现有 `verified_metrics` 保留普通顺序测试的榜单语义。ML、科学计算和 Agent 不会被压缩成与普通题混排的通过数/速度榜；不同指标不互相冒充。公开分享仍需本人主动选择，专业成绩当前保持私有。

## 本地验证门槛

worker 启动探针从 103 项扩展到 123 项：新增 16 项 Agent 协议/资源/隔离检查，及 ML 和科学计算各一组真实参考与针对性错误结果检查。五个 Agent 运行模块和专业探针进入策略摘要与完整回执；缺失任一组不能接受任务。

验收还覆盖真实参考实现、针对性错解、资源超限、API→本地 CLI 公开测试、队列→worker 正式记录、本人进度、跨账号隐私和专业页面。实际 CPU 时间、燃料与输出预约分别展示；本地单 worker 结果不外推成多 worker 吞吐或 GPU 加速证据。
