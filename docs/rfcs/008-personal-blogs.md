# RFC-008：复用社区治理的个人博客

状态：可合并增量；属于 [RFC-006](006-complete-product.md) 的 C2 / PRD R-17，不代表组织课程和第三方题库已完成。

## 本次实现

博客是 `community.Post` 的 `blog` 类型，沿用不可猜测的文章编号及现有正文、修订、状态、评论和治理记录。新文章默认私有草稿；作者明确送审后进入待审，只有具有 `community.moderate_content` 权限的其他审核者可以批准公开。修改已公开文章立即转待审，隐藏、举报、申诉、撤回、删除均复用现有锁和状态转换。不增加直接公开正文的接口，也不改变注册账号或公开主页的默认可见性。

`/community/blogs/` 是已审核公开博文列表；`/community/blogs/<username>/` 是作者的公开博客目录。目录只显示公开文章标题、用户名和时间，不读取私有账号显示名、个人资料或提交源码。没有可公开博文时作者目录统一返回 404，包括仅有私有/待审/隐藏/撤回文章的账号；私有管理仍使用“我的内容”。作者主动送审前，既有表单明确说明审核通过会公开正文与用户名。公开主页的开关不替代博文逐篇审核，关闭主页不撤回独立公开的博文；撤回博文使用原作者操作。

博文可以选择关联题目版本；关联题目下线后文章及目录条目遵循原社区规则停止公开。正文为纯文本并转义；账号导出沿用 community 的 `posts` 字段并保留 `kind=blog`，不导出他人的举报说明。删除账号级联删除本人文字、本人私有举报及文章关联评论/举报/申诉；最小审核记录可保留目标编号、动作、修订与时间，不保留正文或用户名，审核者被删除时 `actor` 置空。

只需 `community` 的 choices 迁移，无新表、权限或数据库授权。界面提供中英文，作者正文不自动翻译。沿用登录、POST、CSRF、长度、写入限流和每页 20 条边界。测试覆盖 HTTP 生命周期、公开目录筛选、跨账号访问、题目下线、导出/删除、分页和中英文；真实浏览器检查应使用可信 bootstrap 的单权限合成审核者，经 HTTP 创建、送审、审核与撤回，不直接改数据库状态。

## 后续边界

组织课程需要独立的组织身份与成员角色（维护者、教师、学员）、邀请/撤销及对象级权限；课程发布绑定不可变内容版本。个人学习记录默认仍私有，教师可见范围与学员退出后的保留策略需明确，不能把 `is_staff` 或社区审核权限等同于教师权限。

第三方题库需独立 RFC 明确稳定命名空间、来源和许可声明、可信维护者及审核权、不可变包版本、依赖/题目版本绑定、包级发布和撤回。导入操作不得使用现有全包替换语义撤回其他来源内容；代码评测策略必须单独经过已有沙箱准入。组织角色、包作者身份和公开运营政策不由本博客增量自动批准。

## 当前验证

独立源码快照中 `test_blogs.py`、`test_community.py`、`test_localization.py` 共 84 项通过；英文目录 681 条均已翻译并编译，无空条目或 fuzzy。真实 Chromium 使用临时 SQLite、本地 HTTP 和仅获社区审核权限的合成审核者完成私有草稿、主动送审、批准发布、英文作者目录、编辑后重新审核、撤回、账号导出和删除文章，随后删除两个合成账号并清理临时服务及数据库。该证据不替代合并后的 PostgreSQL/HTTPS/冻结镜像升级验证。

浏览器入口为 `tests/browser_blogs.py`，接收已有 `BROWSER_URL` / `BROWSER_TEST_SPKI` 规则及 `BROWSER_MODERATOR_USERNAME` / `BROWSER_MODERATOR_PASSWORD`；审核账号必须使用 `community-reviewer-` 合成前缀，脚本会删除它。可沿用 `scripts.browser_acceptance.bootstrap_moderator` 在演练专用数据库创建新审核者。不要复用已经被其他浏览器流程删除的审核账号；全部文章写入和审核仍经 HTTP 表单。
