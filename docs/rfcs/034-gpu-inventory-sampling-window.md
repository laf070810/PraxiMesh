# RFC-034：完整 SMI 查询包围 NVML 采样

日期：2026-11-15。状态：真实诊断完成，采样调整与 321 项组件检查通过；实际 CUDA 重放待完成，见 [ADR-088](../adr/088-gpu-inventory-sampling-window.md)。

`47bdfe2` 的私有诊断明确记录原本地启动失败于 `validate_observation()` 的来源一致性检查。NVML 查询观察到 GPU 进程，稍后的完整 SMI 查询已没有该进程。宿主旁路记录的 PID 494780、NSpid `[494780, 44, 1]` 与原任务 cgroup 一致；GPU 上下文随后结束，任务父进程仍存活。正常恢复成功，原记录在 `test-results/pid-failure-local-diagnostic-2026-11-15/observation-1/`。查询顺序调整本身没有解决两个不同时间样本的冲突。

新版观察使用 schema 3，在原同一三秒期限内依次完成固定 SMI 版本核对、完整 SMI 列表、NVML 三类列表、第二次完整 SMI 列表。完整清单仅取两次完整 XML 列表的并集，保存两个原样本；NVML 的三类 PID 仍必须是该完整清单的子集。不能直接把仅 NVML 出现的 PID 填进清单来满足校验。

两次 XML 中任一正面记录都保留，不能用后一次空列表覆盖前一次列表。只有全部成功且所有样本都为空，才可进入空闲判断；任一查询失败、诊断输出、设备身份变化、超时、额外字段、来源冲突或无效 PID 均失败。完整清单随后仍须逐项通过原宿主身份和 cgroup 核对，读取不到的 PID 不豁免。不存在循环重试、跨调用缓存或期限重置。

旧 schema 1/2 的含义和严格验证保持不变。原 v4 私有挂载声明及管理制品 v2 继续固定同一 NVML/SMI 字节；新增 schema 只描述本次观察的两个 XML 样本，不改写节点绑定或历史成绩。源码身份随实现变化，仍须新匹配镜像的完整启动，不能复用旧就绪。

验证先覆盖开始/结束跨样本、两次 XML 均缺少 NVML PID、前次外部 PID 不得被后次空结果隐藏、部分失败与共同期限，再重放原状态的固定 CUDA 程序。完成实际重放前不宣称问题解决或开放网站 GPU 提交。
