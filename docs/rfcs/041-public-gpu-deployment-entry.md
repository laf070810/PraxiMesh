# RFC-041：统一 CPU/GPU 发布命令

日期：2026-11-15。状态：隔离分支实现与 263 项组件检查通过；须在当前真实升级与中断矩阵通过后补验实际 CLI，再合并交付。决定见 [ADR-095](../adr/095-public-gpu-deployment-dispatch.md)，延续 [RFC-022](022-gpu-release-coordination.md)、[RFC-026](026-gpu-site-hardware-rehearsal.md) 和 [RFC-040](040-initial-gpu-exposure-acknowledgement.md)。

## 目标

已有内部协调流程负责原节点、设备、数据库、两类 worker、候选评测和持久曝光。对维护者继续使用同一 `deploy.py apply/recover`，由冻结包与原状态选择完整生命周期；不增加跳过检查或强制 GPU 激活的参数。当前运行中的验收仍使用原冻结源码，不接入本分支。

## 分派与原状态保护

`apply` 在取得原协调器锁后，先完整核验指定清单和归档。目标包含 GPU，或原当前/前代/候选、配置、运行记录及历史包含 GPU 状态时，选择协调流程。只绑定了新 GPU 节点而尚无 GPU 历史的纯 CPU 安装仍沿原 CPU 流程。旧 CPU 函数继续拒绝 GPU 状态，不能成为备用恢复入口。

GPU 分派在访问数据库之前确认明确的 GPU 配置和已完成的原节点绑定；待完成绑定、缺失配置或未初始化状态拒绝操作。原所有权、配置和运行实例仍由已有生命周期逐次核对，不能为了预检夺取活跃 worker 的设备锁。恢复按原日志选择流程，未知或不完整的 GPU 历史交给协调器拒绝，绝不回退到 CPU 恢复。

命令不执行归档代码，不从当前工作树补旧包能力，不改变内容导入、数据库角色、就绪、任务预约或恢复期限。格式 1 与格式 2 保持各自核验范围，初始化示例目录仍只允许维护者明确选择。`status` 保持无需数据库的原语义。

## 验证与文档

组件检查覆盖 CPU/四镜像选择、GPU→CPU、已退休 GPU 历史、待完成绑定、缺失原节点、未知恢复记录，以及核验和绑定失败发生在数据库访问之前。旧 CPU、GPU 组件、角色和文件中断检查继续适用；分派测试不替代真实硬件。

当前旧包→新包、首次曝光确认丢失、开放前中断和正常 CPU 退出的真实矩阵完成后，制作匹配冻结包，使用实际公共命令验证原站点的 GPU 激活与恢复。用户部署操作统一维护在 `docs/deployment/`；Compose 的独立 PostgreSQL GPU worker 与 SQLite 单机入口仍须明确区分，不能把 CLI 分派当作完整 Compose 集成。
