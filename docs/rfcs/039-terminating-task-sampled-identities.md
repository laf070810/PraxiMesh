# RFC-039：退出期间的当前查询身份

日期：2026-11-15。状态：原失败复现、391 项相关检查及实际 CPU/Docker 故障组合通过；GPU 重放待完成，见 [ADR-093](../adr/093-terminating-task-sampled-identities.md)。

`2210e04` 在原状态上完成资源 OOM 与后续恢复，重放到最后的 service-deadline 场景后，因原 PID 1 的目录消失而拒绝归属。私有位置指向 `OwnedProcesses.check()` 的严格存活分支：故障观察仍先取得完整非空列表，再调用 `require_owned()`，原任务此时已退出。原容器 `cd042823…` 的 Docker 事件为退出码 124，普通恢复完成、GPU 0 空闲。原记录在 `test-results/oom-priority-local-diagnostic-2026-11-15/observation-1/`；不能仅把此事归因于 Docker 延迟，也不能据退出事件补签成功。

正常执行与直接 `require_owned()` 保持原存活条件。仅对已完整触发的固定维护故障，在本次完整查询前绑定原任务 PID 1 的完整身份和 pidfd，并在每个 XML 样本返回时绑定成员。查询中原进程退出时，仍须本次已绑定句柄确认退出和原 Docker 实例确认停止；首次无法绑定的成员、外部成员、重用、权限错误和原记录变化仍拒绝。若查询前原 PID 1 已消失，只能等待原实例明确停止，然后接受完整空清单，不能据此认领任何正面 PID。

若原 PID 已退出而同一 Docker 实例尚未确认停止，只能在原观察绝对期限内等待该实例，不能刷新期限、停止进程或循环查询 GPU 直到为空。原容器确认退出后再读取一次完整来源并要求为空，随后再次核对原停止实例。正面列表不丢弃，未归属的 PID 不豁免，句柄不跨查询保留。

先复现“本次采样成员已归属但原 PID 1 同时退出”的边界，覆盖首次缺失、外部 PID、后次新增占用、Docker 延迟/替换和截止时间，再验证实际 CPU 进程及原 GPU 状态。此路径只确认受控故障的退出观察，不提供执行、准入或 ready 能力。
