# RFC-026：独立临时站点的真实 GPU 整站验收

日期：2026-11-15。状态：实施与真实验收中，完整矩阵尚未完成；原预检失败与同一操作回退见[实际站点记录](../acceptance-gpu-site.md)。依赖 [RFC-022](022-gpu-release-coordination.md) 的内部编排和[当前 GPU 硬件检查](../acceptance-gpu0-startup.md)。

## 目标与边界

本地完整启动和公开样例不能证明网站的角色权限、准入、队列、正式成绩及发布恢复。下一步用新建临时站点实际运行已实现的 GPU 发布组件，保留完整产品门槛。公共 `deploy.py apply/recover` 的 GPU 激活仍保持关闭；不能通过新增任意配置入口开放内部方法。

验收入口只创建自己的站点、PostgreSQL、回环 HTTPS、网络和新 GPU 节点。输入限于完整核验的同源 CPU/四镜像包、固定 Caddy、私有 rootless socket、已授权空闲单卡与新证据目录。它不接受已有站点配置或数据库，不接管本地练习状态、其他 worker、未知容器或预约，不更改原运行站点。

## 使用原部署流程

复用 CPU `Rehearsal` 的临时基础设施、实际 HTTPS 客户端和私有数据快照；GPU 部分经过原节点初始化/绑定、部署锁与数据库操作锁调用内部 `apply_coordinated` / `recover_coordinated`。不得替换判定、就绪、候选轮次、数据库结果、receipt 或权威发布日志。内部调用只用于经过自有资源身份核对的验收站点，不提供通用绕过入口。

先安装 CPU 基线并建立真实账号、草稿和成绩，再实际执行 CPU→GPU、GPU→GPU、GPU→CPU。比较原私有数据、版本目录、CPU/GPU 历史和会话。GPU 候选检查必须经原正式 worker、正常准入和队列完成；其成功仍不替代正式候选内容的参考解/针对性错解验证。

在独立测试库显式发布完整组合候选包，经普通 HTTPS 注册和有限用途令牌调用 `gpu_content_acceptance.py`。保留每次请求键、任务 ID、版本、执行环境及预约结算；结果只来自服务端。正式站点和默认目录不因此发布候选题。

成功切换之后再增加曝光前/后真实进程中断、原 worker 停止与恢复、用户新写入保留等场景。中断只能改变本次原进程的执行时序，不能手改私有状态、删除预约或刷新原期限。分别报告成功切换和故障恢复的实际范围；未通过全部矩阵前不开放公共 GPU 激活。

## 失败与清理

CPU 验收现有的无条件强制清理不能直接套用于 GPU。等待超时或验收失败必须保存原站点、数据库、配置、发布操作、worker/任务身份和请求键。恢复继续原操作，不另建节点或重试不确定提交。

清理前须经原 GPU 生命周期排空、停止、确认进程与设备空闲、确认 journal 无活动任务及数据库无物理预约。成功结束以正常 GPU→CPU 切换和配置退出作为清理边界，再核对所有旧 GPU 对象已停止。只删除完整 ID、标签、镜像和创建身份匹配的自有资源；未知对象保留并报告。原节点锁与历史不作“可删除缓存”处理。

所有重放串行使用授权卡；开始时和原锁取得后重新核对占用。模型、静态制品和历史凭证不算硬件成功，新的源码契约必须使用重新构建的匹配发布包。
