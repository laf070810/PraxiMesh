# RFC-015：Compose 一键本地体验

状态：已实现并通过本地 Compose 验证，2026-10-30；决定见 [ADR-014](../adr/014-compose-preview.md)。范围：README 的本地页面、账号、草稿及社区体验；真实评测和生产发布继续使用已有执行与部署门槛。

## 问题与选择

原 `compose.yaml` 要求操作者先设置基础镜像和密钥，只导入基础题库，并在每次重启时重复导入。这使首次体验需要额外步骤，也可能撤回已有目录中的自定义内容。

采用 Dockerfile 中已固定的 Python 基础版本，Compose 提供相同默认值；保留显式镜像和实例密钥覆盖。容器内用标准库启动器准备本地数据，再 exec Gunicorn。避免要求宿主安装 Python、生成配置文件或运行迁移命令。

## 启动与数据边界

- 按维护者 2026-10-30 的直接访问要求，默认发布 `0.0.0.0:8000`；可用 `PRAXIMESH_BIND` 和 `PRAXIMESH_PORT` 调整监听地址与端口。Compose 的 `APP_ALLOWED_HOSTS` 默认 `*`，以便通过服务器 IP 或主机名访问；可显式收窄，保留 `127.0.0.1` 供容器健康检查。Python 开发环境与生产的主机校验规则不变。非 root、只读根文件系统、最小 capabilities、内存/PID 限额保持；启用 init 回收子进程，不挂 Docker socket。
- SQLite 和自动生成的随机实例密钥放在既有 `app-data` 命名卷中。密钥只在首次生成，权限 0600；不输出到日志。已提供 `APP_SECRET_KEY` 的用户可继续使用原值。
- 只有目标 SQLite 文件不存在时才初始化示例。先在卷内的私有临时目录迁移并导入题库、英文译文、项目和挑战；全部成功后通过同一文件系统的硬链接发布数据库，拒绝覆盖既有目标。失败不会留下半初始化的正式数据库。
- 对既有数据库只运行迁移，不自动导入内容。初始化锁串行化同一卷的启动；路径符号链接与不完整密钥均拒绝。失败退出，不在错误初始化状态启动 Web。
- 启动器只接受本地、SQLite、评测关闭的配置，不进入生产模式。默认关闭 AI。`docker compose down` 保留数据；删除卷是明确的数据删除操作。

采用临时数据库发布，而非“导入完成”标记文件，避免迁移成功、内容导入失败后下次错误跳过导入，也避免重新导入已有用户目录。此入口允许本地自动迁移，不能代替生产协调器的备份、排空和代际恢复。

## 验证

验证初始化中断后可重试、旧数据库不重新导入、密钥跨启动保持且不可经符号链接读取；在真实 Compose 中验证无额外配置启动、完整内容、HTTP/静态资源、容器权限、重启后的账号/草稿/内容/密钥保留，以及测试自有容器、网络和卷的清理。CI 增加同一启动路径的检查；实际托管执行仍需远端环境。

本地结果：55 项启动器/发布兼容性检查通过；`test-results/px-preview-b18b39ed1bf9/result.json` 记录真实 Compose 构建启动、完整目录、九个 HTTP 入口、实际删除容器后重建、原登录会话和私有草稿保留、旧内容撤回状态保留，以及全部自有容器/网络/卷清理。记录中的源码摘要绑定 `compose.yaml`、启动器、Dockerfile 和依赖锁。此次没有启动判题 worker 或模型，也没有重建 F 正式发布包。

同日监听地址修订另经真实 Compose 重放：`test-results/px-preview-d55b7d34d60b/result.json` 确认绑定 `0.0.0.0`，通过宿主非回环 IP 访问九个入口、完成带 CSRF 的同源草稿 POST、拒绝跨站 POST，并在删除容器重建后保留会话、草稿及目录状态。自有容器、网络和卷清理通过；此结果不代替从使用者所在网络验证服务器路由或防火墙。
