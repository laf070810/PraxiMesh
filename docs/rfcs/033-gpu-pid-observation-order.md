# RFC-033：GPU PID 采样与归属核对的顺序

日期：2026-11-15。状态：调整与 293 项组件检查通过，首轮实际 CUDA 重放仍失败；正通过受限私有诊断确认具体读取位置，见 [ADR-087](../adr/087-gpu-pid-observation-order.md)。

## 问题

`f27d085` 的同源四镜像已通过完整归档、无设备 worker 和 CPU 应用验收。原临时站点的新 worker 在首个启动阶段完成前因 `ProcessDisappeared` 退出：完整 NVIDIA 查询后，读取所列 PID 的宿主身份失败。原维护任务清理、CPU 回退、55 张业务表与 33 个序列保留均通过；不将该轮 GPU 启动计为通过。

沿原本地练习状态，用同一实现和固定向量参考解复现。只读宿主观察记录了真实 NVIDIA PID 169252、出生时间 198718443、NSpid `[169252, 44, 1]`，以及它与原任务 PID 1 相同的 cgroup。GPU 上下文只在两个相邻样本中出现，随后消失；原任务父进程继续存活。正常 CLI 返回平台不可用，随后普通 `recover-gpu` 成功，设备空闲。证据在 `test-results/host-pid-local-diagnostic-2026-11-15/observation-1/`。

当前路径在查询前核对原容器，查询后又完整核对一次容器，之后才读取短暂 GPU 子进程的身份。后一次核对包含 Docker/镜像检查，扩大了采样与读取之间的间隔。上述记录支持这一竞态方向，但没有记录失败调用中的确切 PID，须由调整后的真实重放验证，不能直接宣称根因已解决。

## 调整

将完整 NVIDIA 采样纳入 `OwnedProcesses` 的同一次前后身份核对：先确认原 journal、容器实例、PID 1、出生时间和 cgroup；读取完整 PID 列表后，立即读取全部 PID 身份并复读，核对同一原 cgroup 和不变的出生时间；最后再次核对原容器和控制器。

不在完整列表与 PID 读取之间重复插入容器检查。现有直接 `require_owned(pids)` 调用保持原前后核对语义；受控终止观察的专门边界不变。没有 PID 缓存、消失 PID 的豁免、未归属 PID 的重试或空闲替代，也不扩展时间预算。首次读取失败、两次读取不同、外部 cgroup、容器变化、租约失效及取消仍立即失败。

## 验证

用明确的短生命周期时钟模型重现额外检查导致采样过期，并验证新顺序仍拒绝缺失、复用、迁移和原对象变化。模型不证明实际 GPU 成功。之后重放真实 CPU 归属/控制链和原本地状态的 CUDA 诊断，保留所有旧失败；最终仍需新冻结发布包的服务器启动、正式 API 与恢复验收。
