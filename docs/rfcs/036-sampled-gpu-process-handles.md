当前完整观察直到两次 XML 和 NVML 全部完成后才读取成员身份。新版在每个完整 XML 样本返回时立即读取并复读成员身份，同时打开只读观察用途的 Linux pidfd；通过前后完整身份和当前 fdinfo 核对句柄绑定。正面记录仍须来自本次查询，不预取历史 PID、不跨观察缓存、不查询到空为止。

本次观察内已经完整绑定的成员，只有最终读取发现原进程消失且同一 pidfd 明确报告退出，才可确认该样本对应的原成员结束。首次读取缺失、打开句柄失败、身份变化、外部 cgroup、后续样本无法重新核对其 PID、权限或来源错误仍失败。所有样本仍满足原来源子集和并集规则，原任务 PID 1、journal、容器、租约与共同查询期限照常核对。

句柄只存在于一次查询调用，成功或任何异常均关闭，不发信号，不进入持久记录或凭证。无任务的空闲检查保持所有来源必须为空，执行完成仍须原任务清理及新的空闲观察。先用实际 CPU 子进程验证存活、退出、回收与句柄关闭，再重放匹配镜像的完整 GPU 启动；组件和 CPU 进程结果不代表 CUDA 成功。

接口语义依据 Linux [pidfd_open(2)](https://man7.org/linux/man-pages/man2/pidfd_open.2.html)：句柄可观察原进程退出；不能仅凭数字 PID 或句柄存在就断言归属、存活或空闲。
