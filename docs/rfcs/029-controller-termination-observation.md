# RFC-029：控制器故障中的原任务退出观察

日期：2026-11-15。状态：已实施，真实容器与硬件重放中；决策见 [ADR-083](../adr/083-controller-termination-observation.md)。

## 实际失败

冻结版本 `ccf07ef` 的临时 GPU worker 完成初始恢复、资源检查和全部十九项内核检查后，首个控制器退出检查失败。原任务的 Docker 事件确认退出码 70。新诊断定位到 `ContainerDeviceMonitor.observe` 的完整 NVIDIA 查询之后：`OwnedProcesses.require_owned` 再次要求原任务仍在运行，而该任务已按要求退出。原记录保留在 `owned-gpu-site-4/`；旧版本两次同阶段失败的具体原因仍只按各自证据记录。

## 修改边界

正常执行继续要求原 PID 1、出生时间、cgroup、容器启动实例和持久记录一致。退出观察仅在固定维护故障的触发消息完整发送后启用，不能提前用于准备、参考解或正式提交。

退出观察必须复用已经绑定的原进程观察对象，完整读取 NVML 与 SMI。清单非空时仍逐项证明属于活跃原任务；不把失去归属的 PID 当作已清理。清单为空时，允许同一原容器在观察期间从运行变为已退出，但须保留原记录、owner、镜像、命令、启动时间与设备锁核对。只为确认消失的进程定义窄错误类型；权限、格式、PID 复用、cgroup 或对象变化不能由退出分支掩盖。确认原退出后再次读取完整清单并要求为空。

最终故障协议仍分别要求退出码 70、独立硬期限的 124，或断连后原任务仍存活。期限、租约与取消回调不变；原 journal 清理和新实例正确恢复仍须实际完成。观察本身不停止容器、不释放预约、不签发 ready，也不把旧观察对象重新绑定为 idle。

## 验证

覆盖 NVIDIA 查询中退出、进程元数据读取中消失、最后一次状态核对时退出，以及普通模式继续拒绝；分别验证外来 PID、查询失败、重启/替换、记录变化、PID 复用和权限错误。确认触发前仍为正常观察，触发发送失败不切换模式。然后重放真实无设备控制器故障入口，并用新同源四镜像包重新完成实际 GPU 启动与站点验收。组件和 CPU 结果不能代替硬件通过。
