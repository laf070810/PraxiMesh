# RFC-028：未开放 GPU 候选启动失败后的 CPU 回退

日期：2026-11-15。状态：已实施，原临时站点已完成 CPU 回退及数据保留核对；决策见 [ADR-082](../adr/082-unexposed-gpu-startup-abort.md)，实际范围见[验收记录](../acceptance-gpu-site.md)。GPU 启动故障与完整发布矩阵仍待通过。

## 已复现的问题

独立临时站点的 CPU→GPU 发布与随后原操作恢复，都在完整启动的首个控制器故障检查失败。全部内核检查已通过；第二次原测试容器的实际退出码为预期的 70，但 worker 随后以 `SandboxUnavailable` 退出。具体失败条件仍须定位，不能以退出码正确代替完整检查通过。

当前整站恢复先要求候选 GPU worker 完整启动成功，才能冻结候选库并退回原 CPU 版本。因此，未开放、没有正式 GPU 工作的候选也可能让回退停在同一启动故障。原操作、库、worker、锁与任务历史全部保留。

## 有限的中止路径

只适用于原操作曝光前、原目标是已存在 CPU 版本、当前配置仍指向本次 GPU 候选、候选准备停在启动观察且尚未建立候选检查轮次的情形。必须确认原 worker 已退出，不能用此路径停止仍在工作的控制器；不适用于回退到 GPU、已曝光、新操作接管或有未完成工作/物理预约的情况。

先持久保存中止意图，绑定原操作、CPU 目标、完整候选代、配置、owner、原容器与启动实例，以及原恢复记录和准备记录的摘要。之后只通过原生命周期确认停止；持原设备锁核对所有任务历史已完成移除、所有登记对象确实停止。停止等待不持队列行锁。

冻结前仍需本次 token 的实际暂停、完整排空和设备/队列行锁；冻结必须复用 `freeze_gpu`，在同一事务内撤销 CONNECT 并终止 runtime 会话。中止上下文只允许冻结检查识别本次已停止的未完成启动恢复，不给普通配置发布开放跳过入口。冻结完成并再次核对所有条件后，才保存独立的 `aborted` 完成证明。原准备与恢复记录保持原字节，证明以摘要绑定这些失败历史，不把它们改写成 `ready`。

完整中止证明只允许后续原配置退出和 CPU 回退。它不是 `ready`、候选验证成功或设备可用证据。中止未完成时，普通 GPU 启动、原库恢复、配置发布及新操作都应拒绝；重试只继续同一目标，不刷新任何任务期限，不清除任务或预约。旧未完成恢复、未知对象和外部占用不得借此被接管。

## 验证范围

先检查资格拒绝、原对象替换、配置/代/启动变化、原记录摘要变化、活动任务/预约拒绝，以及各持久点 SIGKILL 后的原意图恢复。再用实际 PostgreSQL 验证暂停、冻结和会话/权限边界，最后在保留的原临时站点重放正常回退并比较 CPU 数据。

控制器故障检查的原因和修复另行验证，不能通过中止路径绕过它后开放 GPU。新路径只改变宿主协调器的私有状态机，不改变 worker 可见配置或评测语义；现有冻结镜像继续按原源码契约核验。
