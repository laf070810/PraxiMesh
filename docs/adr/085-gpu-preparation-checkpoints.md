# ADR-085：源码发送前强制检查共享通道时钟

日期：2026-11-15。状态：组件与真实 CPU 容器验证通过，GPU 回归待执行。背景见 [RFC-031](../rfcs/031-gpu-preparation-checkpoints.md)。

`Channel.check(force=True)` 在原绝对期限内立即调用既有检查，并更新原 250 ms 心跳时钟。检查自身的耗时仍计入期限，强制检查不能续期；紧邻发送复用该次检查，后续等待、部分写入和背压继续周期核对。

`KernelTask` 由连接构造器完成桥接前的完整核对。准备身份通过后执行开始回调，再经通道强制检查原容器、配置、journal、租约和完整设备来源，然后发送源码。删除这两处边界前的重复手动检查。取消、身份变化及超时仍阻止源码发送，开始回调中的环境检查、独立正确恢复、原任务清理和最终空闲观察保持原义。

不调整账户预约、会话时限或恢复清理余量。固定时钟与真实 socket 复现原重复检查耗尽执行窗口；修复后的相关 207 项检查通过。该时钟模型不证明真实运行耗时，旧矩阵 Run 的 `time_limit` 及原版本已通过的向量成绩继续保留。须以新冻结包的真实普通 API 结果验证修复，不能用此决定开放 GPU。

真实容器的通信九项、内核调用链二十七项和故障五项全部通过，原容器、镜像标签及临时存储清理通过；本地管道兼容检查另有 61 项通过。证据在 `test-results/checkpoint-observation-2026-11-15/verified-reports.json`。这些结果不访问 GPU，仍需新冻结版本的完整启动及正常 API 验收。
