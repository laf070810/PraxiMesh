# ADR-073：本地 CUDA 编译复用无设备隔离任务

日期：2026-11-02。状态：采纳。对应 [RFC-024](../rfcs/024-local-cuda-practice.md)。

## 决定

本地练习工具新增 `compile` 与 `recover-compiler`。前者复用公开包校验和既有 `CompilationTask`，后者仅按原 journal 清理原任务。两者不访问设备、执行 PTX、发布内容、连接学习数据库或生成成绩。完整本地 CUDA 公开测试仍是未完成的独立功能。

操作者明确指定 rootless Docker socket、不可变编译镜像、状态目录与计算架构。公共题目包没有基础设施配置权。镜像经固定 gVisor/NVRTC 归档构建，身份、无驱动/无设备握手、固定总预算和清理规则复用已有执行链。成功结果等待原任务清理后返回，仅包含受限 PTX 元数据和版本/源码/编译器身份。

工作区使用原文件系统身份派生的逻辑 UUID，复用实际文件锁和 journal；它不指代物理 GPU。持久标记绑定状态、锁、journal 的 inode 及原安装身份和 daemon。初次初始化只允许新目录，完成并持久化后才创建任务；既有目录缺标记、身份替换或活动任务未恢复时均拒绝继续。SIGINT/SIGTERM 由正常回调处理，SIGKILL 后沿原持久记录恢复；不删锁、不采用同名替代、不执行旧镜像来恢复。

`compiled` 与公开样例通过分开：编译成功退出 0，源码编译失败退出 1，平台错误或取消退出 2。原始 NVRTC 诊断和 PTX 不向 CLI 透传；当前只提供错误类别。语义错解编译成功是预期行为。

## 交付与后果

构建、运行状态恢复和实际验收入口集中在[本地编译环境](../deployment/local-compiler.md)，普通练习流程见[本地工具](../local-practice.md)。构建器保留独立镜像及私有构建记录；CLI 模块沿既有源码归档范围交付，不扩大旧发布包必填文件，也不加入 Web 的 Docker 权限。

实际验证必须包含参考解、可编译错解、语法错误、未知架构、镜像拒绝、并发拒绝、SIGINT/SIGKILL 与恢复后的新任务。文件/协议测试只证明其各自边界；GPU 正确性、性能、完整本地运行和产品部署仍需后续独占硬件验收。
