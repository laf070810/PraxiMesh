# ADR-061：协调器 worker 配置绑定原节点与发布代

日期：2026-11-01。状态：采纳；文件、组件和旧制品读取验证通过，完整配置切换与 GPU 升级仍未完成。延续 [RFC-022](../rfcs/022-gpu-release-coordination.md)，证据见 [G45](../acceptance-g45.md)。

节点认领只确定了私有目录的归属，不能证明该目录中的 worker 配置来自哪个发布代。worker 在 Django 初始化、读取配置和取得设备锁之间，也可能遇到配置变化。只比较最初一次读取会继续使用过期数据库或身份。

保留原 `worker.json` schema 1，在协调器管理的状态中增加私有 `deployment-generation.json`。它绑定完整原 owner 的规范摘要、站点、代、数据库、发布摘要、worker 镜像/源码契约，以及完整配置的规范摘要。读取时核对原 mounts 字节摘要、目录与锁 inode 和安装身份；数据库、worker ID 和 worker 登录角色须同属一代。缺任一记录或不一致时失败关闭。

未绑定的独立安装保持原行为。已经绑定的节点不能回退为独立配置；代际文件不能用于生成 GPU 凭证。实际镜像完成源码核验后，其 worker 契约须匹配私有代际记录。Django 初始化保存配置及代际快照，命令开始和取得原设备锁后再次比较完整快照，再进入真实启动。

协调器目前只能在原锁下生成私有配置值和对应记录，不写入或启动。其输入须是支持本协议的已核验冻结发布代；旧包继续可以验证，但缺少该协议源码范围时不能生成协调器配置。后续发布仍须实现实际停止、排空与原数据库无预约检查、双文件持久切换、故障恢复和完整 GPU 验收，才可解除现有激活拒绝。不能用手工拼接元数据替代这一流程。
