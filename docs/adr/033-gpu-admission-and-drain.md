# ADR-033：GPU 健康准入、独立额度与物理预约排空

状态：接受，2026-10-31。依据 [RFC-019](../rfcs/019-gpu-kernel-evaluation.md#网页准入与部署排空)。正式 GPU 内容、硬件与容器部署仍待验收。

GPU 准入使用显式完整 UUID 允许列表 `JUDGE_GPU_DEVICES`，默认关闭，复用现有 `JUDGE_ENABLED` 总开关。`core/gpu_admission.py` 只读设备状态；完整启动后发布的环境必须与设备指纹一致，并匹配当前 GPU 执行策略。空闲设备需新鲜心跳，忙碌设备还需同指纹、同租约、未过期的实际任务及正确预约单位。旧环境、未来/过期心跳、故障或不完整记录均不提供容量。

追加 `core.0005_gpu_admission_environment`，为设备保存不含用户数据和私有凭证的环境。旧记录默认为空，原任务和预约原样保留。`initialize_controller` 在全部启动检查和当前所有者凭证验证后，同一事务发布 ready 与环境；换所有者先清空环境。Web 继续只有设备表 SELECT 权限，已有 worker 表权限涵盖新增列，不扩大全表或管理权限。

新 GPU 任务在现有队列锁下按健康设备的待处理任务数分配，并固定完整执行指纹；后续失联不自动换卡或回退 CPU。每日 `gpu-slot-seconds-v1` 单独计账，Run 90 秒、Submit 180 秒。既有账号/全局待处理上限、幂等性、版本检查、鉴权和 CSRF 继续适用。API 同时提供分别标名的 CPU/GPU 余额；网页按题型显示正确单位。

暂停覆盖两类新任务。部署状态按各自策略识别兼容任务，新增 GPU 健康和物理预约计数，保留原 CPU 字段语义。排空必须等所有设备预约释放，包括已结束或已删除任务；删除设备配置不会隐藏旧预约。恢复需当前 CPU worker、配置中的健康 GPU 容量、兼容任务及无失效物理预约。停止、取消和超时继续不替代真实回收。

这是准入快照，不是独占设备的锁，也不能替代执行前的私有凭证和运行时核对。设备在准入后可能离线；队列保留原指纹并按既有规则等待或超时，执行路径仍独立拒绝失效状态。

验证见 [G17](../acceptance-g17.md)。不占 GPU 的测试只能证明数据库、HTTP、权限、迁移和故障关闭行为；不能据此向实际环境填入允许列表或发布 GPU 题目。Compose 与发布协调器的 GPU 部署接入仍在后续范围。
