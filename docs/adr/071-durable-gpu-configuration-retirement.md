# ADR-071：在原排空与冻结保护下退出 GPU 配置

日期：2026-11-02。状态：采用，内部配置退出；完整 GPU→CPU 发布与失败回退待连接。延续 [RFC-022](../rfcs/022-gpu-release-coordination.md) 和 [ADR-062](062-durable-gpu-configuration-publication.md)。

回到 CPU 版本前必须结束原 GPU 配置的有效状态。仅将 enabled 改为 false 仍会留下旧数据库依赖，使后续新操作无法取得已退休库的旧暂停 token；直接删除文件又无法在中断后确认原对象和退出归属。

`scripts/deploy_gpu_retirement.py` 保存完整发布代、原操作、绑定摘要和原配置快照，按 prepared/retired 两个阶段保留历史。退出仅允许发生在本操作曝光决定之前，且实际维护路由、原设备锁、原数据库冻结、全部 worker 已停止且不能重启、空闲 journal、同 token 暂停和全部任务/预约排空同时成立。普通配置发布不能越过未完成退出；底层文件原语也重新核对退出记录。

复用原配置过渡标记和同一次数据库排空事务，依次移除精确匹配的 worker 配置与代际记录。每次删除均重新核对原内容和标记并 fsync；中断后只接受原始、仅第一份已删、两份均已删三种有序状态。数据库排空锁覆盖两次删除与配置状态确认。未知文件或临时文件一律保留并拒绝，不能认领其他目标。

两份文件确认不存在后，配置日志保存 active=None，清除原过渡标记并再次 fsync，最后保存退出完成。原节点 owner、锁目录、任务 journal、容器登记、数据库、验证和恢复历史都保留。完成重试仍要求原库冻结和全部停止对象；配置已重新发布时，不能拿旧完成记录再次移除它。后续新操作的配置发布仅检查新目标库，不接管旧库的暂停 token。

这一步不启动 CPU 版本、不改变当前数据库或曝光目标。公共 CPU/GPU 发布入口仍拒绝未接入的 GPU 生命周期，包含退出日志；完整 GPU→CPU 升级和 GPU 候选失败回退继续实现，并须真实环境验证。范围见 [G55](../acceptance-g55.md)，检查入口集中在[部署指南](../deployment/container-gpu-worker.md#configuration-retirement)。
