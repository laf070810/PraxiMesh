# ADR-062：GPU 私有配置的有序持久发布

日期：2026-11-01。状态：采纳；文件与进程中断检查通过，真实 PostgreSQL、镜像和完整 GPU 升级待验收。延续 [RFC-022](../rfcs/022-gpu-release-coordination.md) 与 [ADR-061](061-generation-bound-worker-config.md)，证据见 [G46](../acceptance-g46.md)。

配置和代际记录分别原子替换仍存在中间状态。协调器被终止后，如果 worker 读取到一份新文件和一份旧文件，不能继续启动；重新执行发布也不能更换数据库、发布包或凭证来解释现场。

由内部 `Deployment.publish_gpu_configuration()` 持原协调器和设备锁执行。它要求实际维护路由、已登记的原 GPU worker 停止且不自动重启、原任务 journal 无活动或未知记录。数据库操作锁、旧库与目标库的设备表写锁及队列行锁贯穿发布；设备表锁也阻止新设备注册插入；两库必须保持同一操作的暂停 token，且没有待执行任务或物理预约。删除了任务的预约也不能省略。此入口不停止容器、清理任务或决定回退方向，也不提供绕过完整 GPU 发布的 CLI。

部署日志保存非敏感的前后代上下文、配置摘要、文件字节摘要与意图 ID；数据库凭证只进入私有 `worker.json`。节点先建立 `deployment-config-transition.json`，其存在即阻止读取，包括空文件与写到一半的文件。持久化标记后依次替换配置、代际记录，再持久化节点目录和活动代日志；最后移除标记、同步目录并确认意图完成。

恢复只接受原意图中的有序状态：原/原、目标配置/原记录、目标/目标。没有标记的部分结果、未知文件内容、变化的凭证或不同目标均保留现场并拒绝。原意图临时文件只允许匹配完整目标内容或其已写前缀。恢复读取到完整标记也重新同步文件，不能假定被终止的写入者已经执行 `fsync`。已确认目标之后发生中断，可继续完成确认；返回旧代须另开经过完整门槛的切换。

新四镜像制品声明 `worker_configuration: generation-pair-v1` 并包含对应协议源码范围。旧制品保持只读核验兼容，不自动获得此能力。CPU 发布及策略保持原范围。`apply` 仍拒绝 GPU 激活，直至实际 worker 创建、排空、停止、完整启动、队列和升级恢复矩阵接通并通过真实验收。
