# ADR-057：容器 worker 镜像、私有配置与 PostgreSQL 入口

日期：2026-11-01。状态：已采用，专用入口及非 GPU 验证完成；完整设备部署与升级待验收。背景见 [RFC-021](../rfcs/021-gpu-container-supervision.md)，操作入口集中在[容器 worker 部署](../deployment/container-gpu-worker.md)，实际范围见 [G41 验收](../acceptance-g41.md)。

容器后端使用独立 `container_gpu_worker` 命令，精确构造原 `ContainerController` 和 `ContainerGPUAdapter`，复用 `run_worker` 的完整启动、领取、续检、取消与退出。锁在共同生命周期退出后才释放；拒绝低于完整 v4 的管理配置，没有模拟或略过启动选项。宿主命令保持原义。

应用镜像独立于原 CPU 控制夹具，包含固定 CLI、完整管理制品、锁定 Django/psycopg 依赖和应用源码。镜像启动首先核对全部应用源码及原控制器身份，然后加载固定 settings；忽略调用环境中的其他数据库、启用和 Django 配置。任务仍不继承控制器环境、网络或挂载。

Web 和 CPU worker 也须携带完整 GPU 执行策略源码，才能在同一版本上核对数据库中发布的环境。基础镜像构建时只计算文件摘要，Compose 在首次启动和重建后与仓库摘要比较；不因此授予 Web 设备、Docker socket 或运行凭证。

数据库和设备配置来自原状态目录的无链接、0600、有界 `worker.json`。不共享 Web 签名密钥，不把密码放进 Docker 参数或 Compose 展开内容。设置限定 PostgreSQL、显式认证和 TLS 模式；验证证书时使用私有 CA 文件。入口先用只读事务核对实际角色、表/列/序列/转授权限和模型列，再接触设备；不扩大原 worker 授权，不迁移或导入内容。

`--check` 是独立的依赖/数据库预检，既不取得控制器设备锁，也不查询 GPU、执行任务或发布 ready。Compose 的 `gpu-check` 服务没有设备、socket 和 procfs 挂载；`gpu` profile 的正式服务才挂入原私有控制状态和所选管理节点。两者沿用原控制器资源上限，只有可信应用端加入数据库网络。

配置准备默认关闭执行，原子创建且不覆盖已有配置。显式新安装初始化可读取授权单卡的完整管理元数据并建立原安装/锁身份；不能用于迁移未恢复的宿主服务或另建锁目录绕过现有控制器。此功能的设备查询部分仍待授权后实测。首次部署与完整 GPU/候选题目、真实队列、升级和发布协调分别记录验收，不能用数据库或 CPU 结果替代硬件证明。
