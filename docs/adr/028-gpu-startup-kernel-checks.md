# ADR-028：固定 CUDA 启动用例与中断检查

状态：接受组件设计，2026-10-31。依据 [RFC-019](../rfcs/019-gpu-kernel-evaluation.md#正式就绪检查)，证据见 [G12](../acceptance-g12.md)。本次未执行 GPU 工作负载，不授权正式准入。

## 决定

由 `judge/gpu_kernel_checks.py` 统一固定用例、受保护答案和报告校验。`GPUExecutionAdapter.check_kernel` 只使用维护服务；消息只有用例名及新生成的随机挑战，不接收源码或可执行命令。适配器、控制器、正式交互会话与独立恢复沿用同一实现。

十九项用例覆盖向量/矩阵正确解与错解、编译及入口错误、非空公开 Run、最大尺寸、输出伪造、设备堆、非法访存、模块显存不足、无效 PTX、超时、输出超限、取消及附着客户端退出。判定仍由可信控制器进行；外层核对准确用例/挑战、预期 verdict、公开反馈、编译完成、正数计时样本和容器停止身份。32 GiB 模块探针要求驱动内存错误退出码 4，不能把宿主 OOM 代为通过；它针对当前 24 GiB 卡，不是任意显存限额的证明。

取消与附着客户端退出在固定长运行程序编译后触发，只操作本会话保存的客户端进程。取消须捕获专用中断，客户端退出须捕获专用 `GPUDriverExited`；准备失败、提前退出、通道断开及其他平台错误均不算预期中断。随后确认清理前容器仍在运行，实际停止并核对同一容器身份。编译后的等待不单独证明 CUDA 内核正在执行。

每项成功报告等待新的正确解会话、存储关闭、整服务停止和设备空闲。任何清理或恢复失败都不返回成功。GPU 策略摘要纳入新模块；CPU/WASI 策略未改变。已有独立会话探针复用同一题目构造，不改变旧检查记录的版本含义。

## 验证边界

组件测试和实际 CPU 管道证明协议、拒绝及清理顺序；实际 RootlessKit 控制器只验证准备前的连接和拒绝。它们不证明 CUDA 正确性、性能、设备恢复或硬件时限。

还须接入整控制器退出、控制通道失联、服务独立硬期限及恢复，以及完整启动编排、凭证和 worker。完整集合在独占硬件上验证以前，设备保持停用，不生成 GPU 就绪凭证。
