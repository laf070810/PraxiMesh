# ADR-046：本地 CUDA 驱动制品与无设备检查

日期：2026-10-31。状态：接受；五项真实无设备场景、250 项组件检查与最终清理核对通过，实际范围记录在 [G30](../acceptance-g30.md)。背景见 [RFC-021](../rfcs/021-gpu-container-supervision.md)。

容器编译链已能处理 CUDA 源码，但编译镜像刻意没有驱动。为后续 GPU 任务新增独立的本地驱动制品；不修改原编译镜像、监督预算、正式 GPU 策略或历史 journal。

构建器只读取 root 拥有且普通用户不可写的系统目录，以及内核报告的 NVIDIA open 驱动版本。复制前后核对文件身份，静态检查 x86_64 ELF 与固定 SONAME，并重新核对宿主文件以拒绝升级期间的混合快照。初始 `cuda-ptx-driver-v1` 清单包含 CUDA driver、PTX JIT、NVVM 和 GPU compiler；清单固定每库大小、摘要和别名，拒绝额外文件。

任务镜像的运行时标识由独立源码摘要和驱动清单摘要共同计算；原 journal v1/v2 仍保存同样的两类标签和不可变镜像 ID。恢复时无需加载旧库或重新执行旧代码，驱动制品也不能被要求“无驱动”的编译接口接受。

无设备检查只证明固定 runsc 列表包含精确版本、guest 能加载当前库及其动态依赖、原 NVRTC 编译逻辑可用，并能沿既有任务身份清理和恢复。源文件不在宿主执行；guest 不调用 CUDA 初始化，不执行 PTX。实际 CUDA JIT 可能需要额外驱动依赖，须在后续独占硬件验收中确认，不能用本阶段结果签发 GPU receipt。

暂不使用共享 daemon 的 CDI 配置、NVIDIA hooks 或设备透传。后续单卡注入、私有 PID 命名空间下的占用监测、正式环境指纹、完整启动/领取/结算及 Compose/发布协调仍须实现和验证。操作统一在 [GPU 部署指南](../deployment/gpu.md#container-driver)，本地驱动二进制不随项目源码发布。
