# ADR-022：私有控制器命名空间与预约工作目录

状态：接受组件设计，2026-10-31。依据 [RFC-019](../rfcs/019-gpu-kernel-evaluation.md#受信运行适配器)，实际非 GPU 结果见 [G6](../acceptance-g6.md)。正式 GPU worker 尚未交付。

## 决定

外层持锁控制器使用 `OwnedJobService` 启动受信程序；`JobWorkspace.command` 在执行 RootlessKit 前清空继承环境，只保留固定系统路径、语言、并发设置及私有配置/缓存/临时目录。数据库连接、Python 注入、代理及容器远端连接不进入内层。固定系统路径包含 `/usr/sbin` 和 `/sbin`，保证 RootlessKit 可调用 `ip`；不继承操作者任意 PATH 来修复依赖。

RootlessKit 使用独立 user、mount、PID、network、IPC、UTS、cgroup 命名空间，网络为 `none`，不依赖 slirp/NAT 或任务期间下载。控制器在 `/manager` 中，`/workloads` 为后续 guest 保留 0.5 核、512 MiB、零 swap 和 256 PID 上限；外层任务服务继续使用 ADR-020 的独立硬期限与总预算。当前检查读取真实限制，没有据此宣称 GPU 资源或显存配额已验证。

私有路径 socket 可跨网络命名空间，外层依旧读取内核 `SO_PEERCRED` 和宿主 PID 的 cgroup；内层的 UID 0 映射到操作者 UID，不采纳内层自报 PID 作为授权依据。传输仍有帧、总量和时间限制。连接被重置属于平台失败，不能当作完整结果；收到多余数据的固定验证进程退出后，另行确认整个任务 cgroup 无进程。

工作目录名称和规范化身份文件绑定设备、任务、预约、UID 和服务。新任务拒绝覆盖已有目录；重启后的控制器只能按相同预约身份重新打开。每次检查目录所有权、0700 权限、目录 inode，以及身份文件的 0600 权限、单一硬链接和准确内容。清理前必须确认匹配服务已停止、cgroup 为空且没有宿主可见的挂载；递归删除使用目录描述符且不跟随符号链接。部分失败保留身份文件，供后续恢复识别。

这些边界假定操作者账号和平台控制器可信，不防御同 UID 的恶意宿主程序。私有命名空间承载受信控制器，并非学员代码的完整隔离；学员代码仍须在固定 runsc guest 内运行。文件及服务清理也不释放 GPU 数据库预约，必须另行验证设备空闲和正确解恢复。

## 验证与后续

五项实际命名空间检查通过：753,740 字节消息往返、断连终止、额外消息拒绝、停止轮询后的服务硬期限，以及同 UID 的错误 cgroup 拒绝。对应进程树和目录已清理。95 项定向组件检查覆盖目录替换、链接、挂载、部分清理失败、协议及既有服务回归。

此增量纳入 GPU 执行摘要，CPU 策略未变化，不生成 GPU receipt。后续连接离线 Podman/runsc 环境、GPU 会话、设备监测与恢复，再进行独占 GPU、队列和部署验收。
