# ADR-068：候选验证按原启动实例分轮

日期：2026-11-02。状态：采用，内部协议；实际 GPU 与完整发布待验收。延续 [ADR-066](066-gpu-candidate-queue-verification.md) 和 [RFC-022](../rfcs/022-gpu-release-coordination.md)。

原候选检查以操作和 worker 为唯一键，正确拒绝重启前的成绩，但清理后也无法验证同一操作中的新启动。协议更新为 `gpu-deployment-check-v2`：每轮有先持久保存的 UUID，原操作 token 继续控制准入暂停。

轮次加入测试账号/题目身份、管理命令 `--round-id`、响应和协调记录。原启动及环境仍必须匹配；同一操作、同一启动只允许一轮，重试不刷新原任务期限。只有旧轮已 verified 或 cleaned 且 worker 确实出现新启动时，才能建立新轮；只改变 owner 不允许重新入队。每个操作/发布代最多 16 轮，达到上限保留全部历史并拒绝继续。

恢复后清理使用旧轮 UUID 和当前新鲜 owner，不删除另一轮的记录。存在未完成轮次时不能选择另一轮绕过；未知选择器、同一启动对应多轮或损坏记录均拒绝。已清理的轮次本身永远不能作为验证成功。

私有协调记录使用 schema 2，不原地改写旧记录。冻结包须包含 v2 源码；旧包仍可只读核验，但不授予新命令能力。目前尚无公开 GPU 激活入口或已交付 GPU 部署需要自动迁移；遇到旧内部状态应保留并使用其原匹配控制器处理，不能删除记录适配新协议。

结果见 [G52](../acceptance-g52.md)，说明集中在[候选检查](../deployment/container-gpu-worker.md#candidate-verification)。完整候选准备、曝光与回退继续实施；该协议不开放 GPU 提交。
