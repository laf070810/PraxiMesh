# ADR-036：GPU 成绩的独立公开范围与分组计时榜

日期：2026-10-31。状态：接受。设计：[RFC-019](../rfcs/019-gpu-kernel-evaluation.md)。

复用现有 `PublicProfile`、`SharedResult`、逐条确认、撤回和账号数据边界。`metric_kind` 固定区分顺序测试进度与 GPU 批次计时；`showcase.0002` 为旧记录和旧写入保留 `sequential-v1` 数据库默认值。新指标只能由重新预览后的明确分享转换写入，不能随软件升级扩大旧记录的公开范围。

GPU 公开投影先调用正式证据校验，再核对不可变题目快照及其摘要，只接受全部正确的 Submit。每次公开读取重新验证，损坏或指标范围不匹配的记录不再显示。公开字段限定为正确性计数、批次中位数、预热/采样/重复数量及版本、策略和不透明环境指纹；源码、原始样本、编译时间和设备详情仍私有。

榜单以题目版本和完整执行指纹分组。GPU 分数按十进制四舍五入到 0.001 ms，显示分数同时决定排序和并列；每人只取仍公开的最好记录。相同 GPU 分数以分享 UUID 稳定选择代表结果，CPU 原有代表记录选择保持不变。撤回、关闭、题目下线或证据失效立即移除结果，不能拿私人更快的结果补位。

没有新增表、执行协议或资源规则。既有 Web 角色可以管理分享，worker 无权读取公开资料与分享表；迁移和旧 ORM 写入用实际临时 PostgreSQL 核对。这个检查不代表完整旧制品回退，也不等于新 GPU 硬件或部署通过。规则必须说明控制器往返计时、显示精度、固定输入和设备状态等限制，不能称为纯内核基准或能力认证。

相关页面的长按钮允许换行；Django `as_p` 的独立复选框与说明使用同一行的网格布局，保留原标签关联、键盘操作和表单验证。中英窄屏检查与实际 CPU 分享回归见 [G20](../acceptance-g20.md)。
