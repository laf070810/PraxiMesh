# ADR-076：本地 GPU 操作绑定原物理状态

日期：2026-11-02。状态：采纳；可信控制器内部生命周期已接入，外部 CLI/控制通信和完整硬件验收仍待完成。对应 [RFC-024](../rfcs/024-local-cuda-practice.md)。

## 问题

本地公开任务不能借用网站数据库预约，也不能在另一目录创建一套锁绕过原物理设备所有者。进程退出后还须知道原任务属于哪次本地操作，才能安全清理，而不能接管服务端或协调器登记的工作。

## 决定

`judge/container_practice_state.py` 只在操作者明确准备且未使用的原 v4 控制器状态中建立本地绑定。它复用原锁与 journal，保存原目录/锁 inode、mounts 摘要、物理 UUID、安装和 daemon 身份；不初始化另一设备或新锁命名空间。未知记录、worker 配置、receipt 和部署状态均阻止首次认领。worker 配置写入/读取反向拒绝本地标记；协调器沿用原先严格的未使用 journal 检查。

每次执行在任何维护任务之前持久保存新的本地任务/预约 UUID 和完整环境。`judge/container_practice.py` 使用同一身份执行初始正确恢复、共用二十四阶段启动和独立公开任务。必须完成原任务清理，保存操作终态，并再次检查取消、原身份和总期限，才能返回结果。结果始终是非正式公开样例结果，不发布 ready、receipt、学习进度或性能分数。

未完成操作阻止新执行。显式恢复只接受与原操作匹配的 v3 记录、物理设备、镜像和固定内核命令，并沿冻结记录清理原容器；不执行旧镜像、不释放数据库预约，也不声明设备就绪。恢复后下一次执行仍须完整启动。源码/镜像升级可沿用原本地绑定，待恢复任务继续使用原环境身份，不把新镜像套用到旧记录。

## 验证与交付边界

组件验证使用真实私有文件、物理 UUID 文件锁和实际进程 SIGKILL；GPU、daemon 和容器执行为明确模型。另用真实 PostgreSQL 核对原服务端权限/事务，并在真实无设备 worker 镜像中检查本地状态拒绝。原始失败、修复和默认 Compose 重放结果见 [G66](../acceptance-g66.md)，不能把模型或无设备预检当作 GPU 公开样例通过。

当前仍是可信控制器内部接口。面向用户的本地命令、固定镜像/通信、完整资源与硬件验收需要继续接入同一实现；现有 `practice.py compile` 仍只编译，`test` 仍仅运行 WASI。
