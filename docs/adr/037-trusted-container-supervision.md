# ADR-037：先验证可信容器的独立监督与接管

日期：2026-10-31。状态：接受监督基础；完整 GPU 容器部署仍在实施。设计：[RFC-021](../rfcs/021-gpu-container-supervision.md)。

新增的 `ContainerService` 只管理可信监督容器，不替换宿主 GPU worker，也不执行学员程序。GPU 任务最终仍须进入经过完整验证的 gVisor 环境。先独立验证部署基础，可以在不占 GPU 的条件下发现期限、接管和身份问题，而不把未经验证的新路径接入正式提交。

控制端只使用显式、私有、属于当前用户的 rootless Docker socket；空白客户端配置和最小环境防止继承代理及应用凭证。固定本机镜像 ID、入口、用户、runc、只读文件系统、无网络、私有 PID/cgroup、无能力、无宿主挂载及无设备构成此阶段的契约。普通容器只运行可信监督代码和固定 CPU 探针，不能作为学员隔离回退。

容器 PID 1 独立核对绝对启动/终止期限和实际 cgroup 限额；清理不依赖原控制器仍存活。控制端按持久预约身份识别容器，并在观察后绑定实际 ID 和启动实例时间。同名替换、未知配置、daemon 失联或未经确认的停止均拒绝继续，不自动清空设备预约。

七类实际 CPU 检查覆盖限额下的独立终止、子控制器退出、创建者退出、接管、同名替换、错配标签和过期启动；同时核对进程树与自有资源清理。构建与控制都不继承代理变量；构建网络不足时保留失败，不能将凭据传入容器来解决。

当前设备锁只用于自有临时目录中的合成身份。生产环境的 UID/主机身份映射、旧运行制品恢复、可信通信、gVisor 单卡设备、完整启动凭证、数据库/租约，以及 Compose 和发布协调器集成仍须后续实现与实测。不得由此模块生成 GPU 就绪证明。证据见 [G21](../acceptance-g21.md)。
