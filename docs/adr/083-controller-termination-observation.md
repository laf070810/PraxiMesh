# ADR-083：控制器故障触发后的退出观察

日期：2026-11-15。状态：采纳；组件检查通过，真实容器与 GPU 重放中。设计见 [RFC-029](../rfcs/029-controller-termination-observation.md)。

普通执行仍使用 `ContainerDeviceMonitor.observe`，要求活跃原任务的完整进程归属。固定故障检查只有在 `fault-trigger` 完整发送之后，才经 `on_trigger` 切换为 `observe_termination`；准备、发送失败和学员任务不能使用该分支。

新观察只接受已绑定的同一维护任务和 v4 完整 NVIDIA 来源，不新建或更换观察对象。非空清单保持原活跃任务逐 PID 核对；空清单才允许原任务在观察期间退出。`OwnedProcesses.original_state` 仍检查原记录、owner 及 Docker 校验过的完整启动实例。缺失或已退出进程由 `ProcessDisappeared` 表达，保留可读的出生时间和 cgroup；权限、格式和已知身份变化继续拒绝。进程消失只有在原容器明确退出时才可接受，并须再次取得完整空清单。

退出观察不停止对象、不释放物理预约、不生成就绪证据。独立退出码、通信断开存活要求、原硬期限、租约/取消、原 journal 清理及新容器正确恢复继续由原故障协议逐项验证。新源码改变运行时和执行身份，必须重建匹配镜像并重跑全部启动；旧 21 阶段结果不能拼接为新版本通过。

原进程归属比较允许 Docker 的 `OOMKilled` 从 false 单向变为 true，但只有前后仍为同一活跃 PID 1、出生时间、cgroup 和完整容器契约时才成立。原状态标志保留，其他字段变化及标志回退仍拒绝；整个任务停止不能由此通过。固定控制器故障的 `oom_killed=false` 要求不变，资源检查继续独立验证限额、清理和恢复。实际资源诊断按宿主 procfs 读取并散列 cgroup 文本，不套用容器命名空间内的解析器或将文本作为路径。
