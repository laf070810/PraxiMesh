# ADR-063：GPU worker 容器的原实例生命周期

日期：2026-11-01。状态：采纳；文件、锁与协调器进程中断验证通过，真实 Docker、PostgreSQL 和 GPU 生命周期待验收。延续 [RFC-022](../rfcs/022-gpu-release-coordination.md) 与 [ADR-062](062-durable-gpu-configuration-publication.md)，验证范围见 [G47](../acceptance-g47.md)。

配置发布完成后，创建和启动容器仍可能在 Docker 返回与协调器保存之间中断。只凭同名对象重试会误认外部替代容器；启动时继续持有设备锁，又会阻止正式 worker 获得它。停止容器也不能证明原任务及数据库预约已经清理。

内部 `Deployment.gpu_worker_runtime()` 由 `scripts/deploy_gpu_worker.py` 实现，分别记录固定 `--check` 预检和正式 worker。使用原 rootless socket、临时空 Docker 客户端配置及限定环境，不把数据库凭证放入参数或容器环境。预检只读挂载私有状态并连接内部数据库网络；正式 worker 使用固定状态、socket、递归只读 procfs 及原单卡管理映射。两者均要求固定镜像、只读根、资源上限、最小权限及禁止自动重启。

创建前持久保存原代、完整配置记录、网络 ID、镜像配置摘要、专用意图标签和固定参数；完整运行契约核验后先保存容器 ID，再允许启动。丢失创建响应只可找回同一意图且从未启动的对象。已登记容器丢失、未知同名对象或运行契约变化均拒绝，不自动删除或重新创建。

启动要求原维护路由、数据库操作锁与原暂停 token；正式 worker 还须有对应配置的成功预检。先持设备锁核对配置并保存启动意图，再释放设备锁，让 worker 自行取得原锁。保存启动前时间，重试检查同一容器的新启动实例；即时退出、暂停或重启中状态不算运行成功，也不产生 GPU 就绪。

停止先保存原 ID、运行契约和启动时间，只停止并确认该实例。暂停检查通过短连接完成，不持队列行锁等待 worker 退出，也不抢占其设备锁。任务 journal、物理预约和就绪撤销仍由原 worker 的清理与恢复协议处理；控制器不能因 Docker 已退出自行清空。配置发布同时检查预检与 worker 记录，未确认的创建、启动或停止须先沿原意图恢复。

此决定只建立内部生命周期组件，没有新增对外命令，也未接通完整 GPU `apply`。实际无设备镜像/数据库检查、完整启动、排空、队列、回滚和曝光后的恢复仍须分别验收；测试模型的 Docker 状态不能作为这些验收的证据。
