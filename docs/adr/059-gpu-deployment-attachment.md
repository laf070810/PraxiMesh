# ADR-059：GPU 协调器绑定原节点身份

日期：2026-11-01。状态：采用节点绑定决策；完整 GPU 代际激活与恢复继续实施。背景见 [RFC-022](../rfcs/022-gpu-release-coordination.md)，操作集中在[节点绑定指南](../deployment/container-gpu-worker.md#coordinator-binding)。

通过独立 `attach-gpu` 为原部署配置增加单卡节点，其他字段仍受原摘要约束。绑定不读取设备、不启动服务或连接数据库，不发布就绪。已有活动发布操作须先完成；绑定未确认时，发布、恢复和维护在访问数据库之前拒绝。

首次绑定只接受未配置 worker、未执行任务的完整 v4 私有状态。复用原 lock、安装身份、rootless daemon、挂载和宿主进程视图；只认领同一站点 ID 和同一部署状态目录。不能用复制目录、创建第二套锁或清除原任务记录迁移已有 GPU 安装。

部署侧意图先落盘，节点侧所有权记录在原设备锁下原子发布，最后确认配置摘要。中断后仅允许同一意图重试；临时文件名绑定该意图，不能清扫其他文件。已确认记录缺失或改变时拒绝重新认领。独立 worker 配置工具拒绝写入协调器已认领的状态。

新安装准备可使用 `--prepare-only --initialize`，保留原设备身份初始化流程、暂不写数据库连接。这仍会读取真实 GPU 元数据，需原有明确授权；无设备验收使用独立合成元数据和真实文件锁、daemon 身份及进程中断，不授予执行能力。

GPU 发布激活门槛暂不移除。私有配置的代际切换、原数据库预约恢复、候选完整启动和正确/错误 GPU 队列检查必须继续接通并单独验收；绑定成功与制品导入成功都不能代替这些条件。当前证据及尚未完成范围见 [G43](../acceptance-g43.md)。
