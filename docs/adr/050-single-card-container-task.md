# ADR-050：单卡容器任务与持久设备记录

日期：2026-10-31。状态：设计接受，设备实测尚未通过。背景见 [RFC-021](../rfcs/021-gpu-container-supervision.md)，当前结果见 [G34](../acceptance-g34.md)。

将设备配置作为原任务身份的一部分。固定 `single-cuda-device-v1` 只包含完整物理 UUID、驱动、卡 minor 和内核注册的 UVM major。外层 Docker 与内层 OCI 从同一配置生成三个字符设备：所选 `/dev/nvidiaN`、`nvidiactl`、`nvidia-uvm`。不接受任意路径、全部 GPU、设备请求、通配规则或额外能力。

原 CPU 服务继续拒绝设备。单卡服务使用独立源码/驱动清单镜像身份和既有任务总预算；原无设备驱动/编译镜像不能被当成单卡镜像。可信控制端从 v4 完整进程来源的原设备身份及固定宿主 procfs 视图构建设备配置，自己不新增 UVM 挂载；任务检查实际节点、当前内核与固定驱动快照，再启动嵌套 runsc。

持久 journal v3 在原实例、命令、镜像、安装和锁身份外保存设备配置与任务预算；v1/v2 原义不变。独立恢复使用保存的映射核对 Docker 实际状态，只有完全匹配才停止或移除。恢复不加载新驱动、不运行旧镜像，也不因当前新镜像摘要变化认领另一实例。数据库仍先停止原对象，再核对隔离状态、所有者与原预约，归档不等于设备可用。

嵌套 runtime 只允许当前固定驱动版本的 nvproxy，能力限定为 compute/utility，禁止 legacy 自动注入；保持私有 PID/网络、只读根、既有 seccomp 与总预算。配置可用于后续 CUDA 会话，但节点可见不证明 ioctl 隔离或内核正确执行，仍需完整启动与硬件验收。

镜像预建空普通文件作为设备绑定目标，以便 runsc 在只读根上挂载所选设备；这些文件本身不是字符设备，也不授予设备权限。实际 guest 的 `/dev` 必须只出现配置中的三个 NVIDIA 字符设备，不能把镜像内其他空目标暴露为可用设备。此修正来自首次真实运行的只读目录创建失败，不改变外层只读根或增加能力。

设备验证使用固定 CPU guest，只读取设备节点元信息，不能打开 NVIDIA 设备、创建 CUDA 上下文或运行内核。它仍接入真实设备，必须取得明确授权；“不占 GPU 的开发”不自动涵盖该操作。必须同时检查原任务归属、控制器异常退出后的记录恢复和新调用；静态替身不能代替实际任务和数据库边界。操作集中在 [GPU 设备节点检查](../deployment/gpu.md#container-device-nodes)。
