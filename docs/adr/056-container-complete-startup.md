# ADR-056：容器完整启动、私有凭证与就绪发布

日期：2026-11-01。状态：已实现，组件、实际 PostgreSQL 与无设备控制镜像重放通过；完整 GPU 和容器部署仍待验收。背景见 [RFC-021](../rfcs/021-gpu-container-supervision.md)，结果见 [G40](../acceptance-g40.md)。

`core/gpu_readiness.py` 保留共同的二十四阶段顺序、每阶段 180 秒与总体 4320 秒期限、私有凭证发布和最终数据库事务。精确适配器类型选择宿主或容器流程，不接受仅含相同方法的对象。宿主原有凭证、systemd 服务和资源报告继续保持原含义。

`core/container_startup.py` 先按原 journal 停止旧容器，在数据库所有者与预约核对后完成归档，再运行新维护容器的正确恢复。数据库失败仍尝试停止原实例，但不归档或释放预约；清理前后完整观察设备空闲，未知进程不被终止。未完成的宿主任务或来源不明的旧状态不能改写为容器指纹后重试。后端迁移只接受原宿主已完成恢复、没有预约的 ready 状态；容器升级可依据原完整环境接管。只有尚未发布环境时才允许使用绑定原预约的 v3 journal，不能用它覆盖已有宿主身份或非空损坏环境。

容器阶段报告使用独立 envelope，包含原容器 ID、nonce 与归档。资源检查保留适配器产生的随机挑战并复核目标与全部九项测量；十九项内核和三项控制器故障复用各自严格校验器。故障中的新恢复仍须换实例。初始维护恢复保持 `ready=false`；所有阶段、原实例清理和环境复核成功前，旧任务、预约及额度不释放。

容器私有凭证采用 schema 2 和独立套件身份，绑定完整环境、执行策略、worker、持锁令牌、原控制端挂载和 journal 安装身份。host 字段来自固定的宿主 boot ID、映射操作者及引擎内核；容器 UID 0 不能冒充宿主 root。共用 0700/0600、无链接、原子发布、双时钟与完整任务余量的校验。凭证仍是可信进程的私有记录，不是对同 UID 管理者的签名证明。

文件发布后，在同一设备行锁事务中核对原预约、确认恢复并发布环境。失败撤销本次凭证并保持隔离，不覆盖替代所有者。空闲心跳和领取检查当前凭证、原控制端及完整设备列表。Web 只读取当前策略、发布环境和新鲜健康状态；不能靠保存的历史成绩环境开放队列，也不能读取私有凭证或使用 Docker socket。

数据库及序列化测试使用明确的 GPU 运行时替身和合成账号。真实 CPU 控制镜像检查只验证源码依赖、锁与恢复，不证明 CUDA、完整 GPU 时间预算或性能。专用容器 worker 命令、数据库连接配置、Compose、发布升级和独占 GPU 验收仍需继续交付。
