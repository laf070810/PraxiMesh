# ADR-074：本地公开样例使用独立 GPU 任务协议

日期：2026-11-02。状态：采纳；本地命令、完整启动接入与 GPU 验收仍待完成。对应 [RFC-024](../rfcs/024-local-cuda-practice.md)。

## 问题

CUDA 下载包只有公开样例，既有 `execute` 请求要求题目同时含公开与受保护测试。直接调用被拒绝；补造受保护测试会改变正式任务契约，放宽原校验则可能让不完整题目进入 Submit。

## 决定

增加 `execute-public` 请求，固定 `mode: run`。它只接受既有六个执行字段、至少一个公开测试及合法源码；任何受保护测试、未知基础设施字段或 Submit 模式都被拒绝。`execute`、正式内容和学习证据的原校验保持不变。

`evaluate_public_kernel` 和正式评测共用可信数值比较；guest 只接收编译源码与输入，不接收预期答案或自报 verdict。公开执行不进行性能批次，不生成可提交的成绩。完成响应必须含布尔 `formal_result: false`，不能与普通任务的完成响应互换；容器适配器另行返回本地公开范围。

新增路径复用原 `KernelTask`、开始回调、环境/任务身份检查、固定资源预算及恢复。结果必须等原 guest 停止、新正确 guest 恢复、外层原容器删除、进程清理与空闲观察完成后才返回。调用者仍须持原物理锁并完成完整启动；这一协议不授予设备就绪或产品准入。

## 验证和交付

协议、比较、响应混用和清理次序先做组件检查，再用[CPU/runsc 调用链检查](../deployment/gpu.md#container-kernel-flow)重放公开正确、错误、异常、取消、恢复失败及模式/受保护测试拒绝。固定 CPU guest 将源码视为不透明数据，不编译或执行它，不能作为 CUDA 正确性或性能证据。

新增方法位于原有有序源码范围内，相关 GPU、控制器、worker、运行时与编译镜像契约随字节变化；旧镜像必须被拒绝，重新构建后再运行相应检查。CPU/WASI 策略和历史版本成绩的解释不变。完整本地命令仍需持久任务恢复、二十四阶段启动及真实 GPU 验收后交付。
