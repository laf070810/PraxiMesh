# ADR-097：Compose 数据库初始化使用独立最小生命周期

日期：2026-11-16。状态：分支实施中。关联 [RFC-042](../rfcs/042-complete-gpu-compose-site.md)。

整站 Compose 增加一次性 `bootstrap` 服务。只有 PostgreSQL 与该服务收到数据库所有者凭据；Web、CPU worker 和 GPU worker 等待其成功，并只持有原有最小角色。初始化复用 `scripts/deploy_database.py` 的所有权、数据库操作锁、角色与表/列权限定义；新增容器内连接入口仅连接本安装的固定 PostgreSQL 服务名，不为运行时角色增加权限。

安装意图和阶段在 PostgreSQL 的独立私有 schema 中事务保存，绑定安装、代际、冻结源码和完整准备配置。新空库才执行迁移与明确选择的示例导入，全部步骤成功后授予运行时连接。同版本重试沿原阶段继续；完成后的启动只检查迁移与权限，不重复导入。数据库或元数据缺失、身份变化、不同源码均拒绝自动重建或迁移。没有成功提交身份标记的数据库不被认领。

初始化服务不接触 Docker socket、GPU、设备锁或任务 journal，不发布任何就绪凭证。它不负责升级正在使用的数据库；版本维护与备份恢复仍须单独实现并验收。组件、真实 PostgreSQL 与实际 Compose 启动分别记录，不能互相替代。

准备工具另建一个原宿主用户私有的初始化标记目录。初始化服务仅在已核验的 rootless daemon 中以映射到该用户的 UID 0 运行，保留只读根和全部 capability 删除，仅此目录可写。标记绑定原目录 inode 与配置摘要，并在创建应用库前持久确认 PostgreSQL 元数据已建立；此后元数据丢失（包括整个 PostgreSQL 卷丢失）不能重新当作首次安装。Web/worker 仍为镜像的非 root 用户，不获得该目录。

分支验证：原数据库组件 66 项通过；新初始化和原数据库权限/复制共 23 项真实 PostgreSQL 检查通过，另有迁移完成、授权完成两处实际子进程 SIGKILL 后重试通过。授权响应丢失时保留现有运行时连接与新写入。两轮自有测试容器和卷均清理。实际冻结镜像及 Compose 运行仍待验证。

宿主标记增量另行通过 27 项真实 PostgreSQL 检查（含上述中断和两种元数据丢失）及 46 项文件/配置检查。生成的四种服务组合经实际 Compose 解析；环境文件中反斜杠重复转义的失败已用固定 CPU 容器复现并修正，六种引号、反斜杠、美元符和中文值在容器内逐字相同。原 `7e1aff0` 冻结包的完整 CPU 应用通过不覆盖这个新增标记协议；新增协议仍需自己的冻结镜像与整站验证。
