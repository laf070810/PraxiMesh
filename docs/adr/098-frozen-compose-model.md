# ADR-098：准备时固定 Compose 的实际配置

日期：2026-11-16。状态：已实施，实际固定配置的 CPU/AI 重建与 GPU 首次启动通过。关联 [RFC-042](../rfcs/042-complete-gpu-compose-site.md)。

已在临时安装的只读配置解析中复现：宿主 `PRAXIMESH_WEB_IMAGE` 会覆盖 `--env-file` 中准备好的镜像。原服务没有变化，但这意味着环境文件本身不足以保证下一次启动使用原固定镜像。

准备工具在空白客户端和最小环境中调用实际 Compose 解析器，保存包含已解析角色配置的私有 `compose.json`，核对项目、服务集合与不可变镜像。后续命令显式指定该文件、原项目名和 daemon；普通宿主变量不再替换镜像、服务路径或数据库配置。保留原环境文件和冻结源码，便于审阅；`compose.json` 包含凭据，须保持 0600，不能公开提交或打印完整配置。

同一原始配置可确定性生成该派生文件；已有内容不同则拒绝覆盖。原数据库、宿主初始化标记、设备锁和 worker 配置的恢复规则不变，不能通过重建派生 Compose 文件重建数据库或跳过原状态。生成的 `compose.sh` 只传递固定 Docker/Compose 参数，不执行归档代码或学员源码。

这属于准备工具的修正，应用与初始化协议保持不变，可对实现匹配协议的既有冻结包生成配置。实际 Compose、宿主变量覆盖拒绝及同版本数据保留须另行核对。

验证：53 项文件、配置及模型拒绝检查通过；原临时安装的实际模型在冲突宿主变量下往返解析后完全一致。包含特殊字符路径的 CPU/AI 与合成 GPU/check 模型也通过，检查 profile 保留且默认不启动。随后独立新站点用生成脚本在冲突宿主环境下完成实际 CPU/AI 重建；GPU 组合首次完整启动与两题 API 也通过，范围和仍待完成的重建见[Compose 验收](../acceptance-compose-postgres.md)。
