# ADR-078：宿主命令保留原客户端与物理状态身份

日期：2026-11-02。状态：已采用，外层组件已实现，完整启动器实施中。对应 [RFC-024](../rfcs/024-local-cuda-practice.md)。

宿主命令与控制容器不能同时持有物理 GPU 锁。宿主在原 journal 中建立独立的客户端互斥文件，固定其 inode、随机身份及原本地状态摘要；它只串行化本地命令，不新建物理锁命名空间。首次建立时仍取得原物理锁，之后将其交给控制容器。

`judge/container_practice_host.py` 绑定原 v4 挂载声明、目录、socket、daemon、安装和本地标记。控制容器持有物理锁时，宿主仍可取得客户端锁，检查身份并按原记录清理控制容器；需要读写内部操作时才重新取得原物理锁。缺失或替换的原锁、目录、客户端文件和标记均不能重建认领。

外层调用记录在客户端锁内原子保存并同步磁盘，写入前核对旧记录，避免覆盖未经确认的变化；记录固定客户端锁的身份。进程退出只释放锁，不删除记录，也不清除内部任务或服务端预约。共享的挂载与标记验证器区分布尔值和整数，恢复不能利用 Python 相等比较更换身份。

`judge/container_practice_controller.py` 在原物理锁内记录固定创建意图和完整 ID，保存启动意图后释放物理锁，交给容器内入口。记录绑定冻结镜像配置、创建时间、完整容器配置及首次观察到的启动时间；重开旧意图只能清理，不能启动或重放。原 ID 与名称同时查询，容器改名、替换或重启均不能误认成已清理。停止和移除分别先落意图；响应丢失后只确认原操作，不执行旧镜像或清除内部任务。

文件、文件锁与 SIGKILL 后重开使用真实进程检查；Docker 模型验证拒绝与恢复边界。另有[固定 CPU 容器检查](../deployment/gpu.md#local-controller)验证实际外层生命周期，明确使用测试入口和合成设备声明。完整管道调用、成功退出与内部终态联合确认、公开 CLI 和硬件执行仍待完成；客户端锁、完成帧或控制容器移除都不产生就绪和成绩证据。
