# ADR-023：共用离线 GPU 运行模块与容器回收

状态：接受组件设计，2026-10-31。依据 [RFC-019](../rfcs/019-gpu-kernel-evaluation.md#受信运行适配器)，证据见 [G7](../acceptance-g7.md)。CUDA 硬件重放、设备恢复及正式 worker 仍未完成。

## 决定

固定 runsc、Python OCI 和 NVRTC 校验集中在 `judge/gpu_artifacts.py`，既有组件探针保留命令入口并复用这些函数。运行模块先把有限大小的普通归档复制到私有工作目录，再验证完整制品；拒绝 FIFO、链接、超限或变化的输入。固定完整 runsc 归档与 sidecar 保持一致，镜像校验覆盖清单、配置和全部层，禁止任务期间拉取镜像。

`PrivateRuntime` 只在受信任务的 RootlessKit 命名空间内准备独立 Podman 存储，固定使用 runsc、cgroupfs、空 hook 目录和自有 CDI 目录。命令明确禁用远端连接；隔离子进程使用独立空 home 和配置目录。这样既能满足镜像库的配置查找，也避免读取操作者的 registry 或容器配置。

容器以 UID/GID 65534、只读根文件系统、无 capabilities、禁止新增权限、无网络和 IPC、无容器日志运行。实际镜像、运行时和资源参数在创建后和启动前核对；资源上限同时保留在受信 workload 父 cgroup。正式 CUDA 会话必须显式准备受支持单卡、CDI 和固定 NVRTC；未准备 GPU 时拒绝 `kernel_session`，不提供 CPU 降级评分。

控制命令的输入、输出、错误输出和等待时间受限，等待期间检查取消和预约期限。原始诊断不进入异常文字或学员结果。清理可以跳过已经取消的业务回调，仍受绝对任务期限及独立用户服务期限约束。

输出超限时，满的附着管道可能妨碍 conmon 完成退出。因此会话先关闭管道、终止并等待自己持有的附着 CLI，随后无条件核对并终止、等待自有容器。即使 CLI 已退出或终止失败，也不能省略容器检查。每个容器按已记录的名字/ID、固定镜像和隔离属性核对；只清空该私有存储中的自有容器和镜像，随后在同一命名空间内回收挂载和映射 UID 的文件。

## 验证与边界

固定 CPU guest 复用同一镜像校验、容器配置、`GPUSession` 管道和清理路径，实际验证文件/网络/设备边界、输出超限、超时、取消、客户端退出、CPU 节流及临时存储限制；每项之后创建新容器核对重新运行。该夹具不接受任意可执行程序或学员源码，不初始化 CUDA、启用 nvproxy 或映射 GPU。

七项真实检查和十四个容器清理通过，164 项相关组件测试通过；命名空间五项复验也通过。CPU 策略保持不变。CPU 重新运行不作为 GPU 正确解恢复，下一步仍需将单卡会话、占用监测和恢复接入外层任务控制，并在独占条件下完成真实 GPU 验收。
