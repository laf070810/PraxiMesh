# ADR-060：在原数据库恢复中重建无状态 Web

日期：2026-11-01，验证状态更新于 2026-11-02。状态：采纳；组件、真实容器专项及当前 CPU 完整发布恢复矩阵通过。背景见 [RFC-023](../rfcs/023-web-container-recovery.md)，证据见 [G44](../acceptance-g44.md)、[G58](../acceptance-g58.md)、[G59](../acceptance-g59.md)。

RootlessKit 的重启端口冲突可能留下 running 但无发布映射的容器。恢复路径采用维护期间的有记录重建，不对同一失败网络状态反复 start，也不从请求配置推断实际端口。

重建只作用于已经停止、契约符合的无状态 Web，沿用原代镜像、数据库和配置。旧容器的完整 ID 和配置摘要先保存，移除前再核对；不用 force 或 volumes。新容器先 create、核对并保存 ID，再 start。实际映射、HTTP、原 worker 的新鲜隔离检查及可信功能验证仍是开放代理的条件。

每代最近的重建记录独立于当次发布操作保存。中断后只认原 ID 或匹配原随机意图和完整契约的新对象；已有新 ID 时不接管同名替代。未知挂载、身份或运行配置均拒绝自动处理。已曝光的数据库保持原库，候选曝光前仍按原协议恢复上一代。

代价是恢复期间增加一次轻量 Web 创建和新的内部端口，数据库、代理维护窗口和 CPU worker 的完整启动规则不变。暂不推广到持有任务状态的 worker、GPU 控制器或任意外部容器。实际验收未完成之前，不将组件通过视为端口故障或完整升级已经解决。
