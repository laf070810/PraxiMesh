# ADR-025：GPU 执行适配器与结算边界

状态：接受组件设计，2026-10-31。依据 [RFC-019](../rfcs/019-gpu-kernel-evaluation.md#受信运行适配器)。本轮没有执行 GPU 工作负载，证据范围见 [G9](../acceptance-g9.md)。

## 决定

`GPUExecutionAdapter` 在宿主侧保留设备锁、任务服务、占用监测和数据库回调；`gpu_controller_entry.py` 在无数据库凭据的私有命名空间中加载可信控制器。学员代码始终通过固定的 CUDA guest 编译与运行，受保护答案只在控制器内比较。

适配器身份包含单卡 UUID/型号/驱动/架构、完整 OCI 图身份、runsc/NVRTC/执行文件摘要、Podman 版本、会话策略、父 cgroup 限额、时间预留及控制器源码摘要。配置或代码变化后拒绝复用。数据库任务的执行指纹必须与其一致；正式启动 receipt 尚待补齐，该指纹本身不能开放题型。

私有通道按连接、准备、执行、完成的固定顺序交互。外层核对真实对端及服务 cgroup、控制器源码和准备后的完整身份，检查租约并登记开始执行后，才发送代码与测试。准备阶段不包含学员数据；数据只通过有界 IPC 传递，不写入参数、环境、日志或工作目录。消息和身份使用严格 JSON 表示比较，避免布尔值等被当作整数。

准备、运行、设备恢复与文件清理共享原预约的绝对期限。内层从原期限预留 35 秒用于独立恢复、10 秒用于存储清理，外层另留 12 秒用于控制器结束与服务清理。学员会话仍受既有 Run/Submit 上限限制，实际剩余时间可能更短；不能在准备或重试之后重置时间。这组预算尚待真实 GPU 时序验证，未将其作为已验收的产品时限发布。

学员 guest 已停止后，用新容器编译固定向量正确解、执行 257 元素运算并比较结果。只有独立恢复和私有存储清理成功，内层才返回结果；外层再核对公开反馈/采样字段、完整服务停止与设备空闲。结果白名单不接受私有测试名、源码、额外字段或 guest 自报计时。Run 和非全对 Submit 不返回性能样本。

`core/gpu_execution.py` 将这条路径连接到现有短事务控制。结果必须在物理恢复完成之后才能结算，过期租约不能写入候选成绩。出现故障时先停止所观察的同一服务实例，再尝试隔离停用；不能按名字重新构造服务对象而丢弃既有调用身份。清理或数据库操作失败继续保留预约，后续接管还须完成真实设备恢复。

## 验证与未完成项

协议状态机与拒绝边界、实际 PostgreSQL 结算/取消/账号删除/权限/锁等待已检查。真实命名空间检查只证明新入口可以加载、进行对端核对并在准备前拒绝错误顺序；没有调用 NVML、创建 CUDA 上下文或运行 GPU guest。数据库测试使用替身适配器，只验证事务及调用顺序，不证明物理恢复。

当前尚无正式 GPU worker 启动命令、启动 receipt、已发布 GPU 内容或产品准入。恢复阶段、完整执行预算、硬件故障、性能、队列及部署都要在维护者允许的独占 GPU 上继续验收。
