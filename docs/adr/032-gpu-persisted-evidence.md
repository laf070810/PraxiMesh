# ADR-032：GPU 持久成绩与版本化学习证据

状态：接受，2026-10-31。依据 [RFC-019](../rfcs/019-gpu-kernel-evaluation.md#持久成绩与学习证据)。GPU 完整硬件与提交准入仍待验收。

`core/gpu_evidence.py` 验证正式 Submit 的结束状态、创建/领取/执行/完成顺序、已消耗的 GPU 整卡预约、任务租约身份和结果/环境摘要。通过 `core/result_evidence.py` 接入现有学习、课程、挑战与本人 API/导出，不复制另一套进度。公开 Run 可以显示公开反馈，但不是正式完成证据；平台故障和不完整记录不计入。

历史环境使用已保存的运行时、制品、硬件和执行摘要，校验结构及其与任务指纹的一致性，不要求历史执行摘要等于当前文件。会话配置由不可变 `PROFILES` 注册表解释；新语义追加版本，旧定义保留。验证不会打开旧制品或执行用户源码，也不是客户端上传成绩的认证途径。

运行时与持久记录共用严格结果校验。接受成功必须有完成编译的正耗时及完整正数采样，公开反馈必须与可达的用例数量一致。GPU 正确性循环完成后仍可能在预热或重复批次失败，因此保留全部正确性通过但最终 `wrong_answer` 的合法记录；它只计尝试，没有性能分数。

只显示已校验的固定结果字段，拒绝隐藏用例名、原始日志、未知嵌套字段、损坏采样或摘要。成绩页区分编译初始化和控制器批次往返中位数，明确通信/同步成本；GPU 预约以整卡秒数展示。GPU 结果继续排除在传统用例通过量榜单之外，后续性能榜单须固定题目版本和执行环境并保留显式公开/撤回。

验证见 [G16](../acceptance-g16.md)。数据库中的成绩和浏览器计时均明确为合成测试，实际 CPU/WASI 重放只覆盖共享代码的兼容性。没有发布 GPU 题库、开放网站 GPU 提交、签发 GPU 凭证或完成容器部署；这些门槛继续保留。
