# ADR-005：单一代理信任边界与真实 HTTPS 部署验收

状态：接受，临时回环部署已通过；公开发布另行验收。日期：2026-10-23。依据：[RFC-003](../rfcs/003-production-acceptance.md)，补充 [ADR-003](003-operations.md)。

生产流量经 Caddy 到私有 Gunicorn 后端。代理无条件覆盖 X-Forwarded-Proto、X-Real-IP；应用最前面的中间件校验连接地址及单值协议，再交给 Django 安全/CSRF 中间件。Gunicorn 禁用独立的代理协议推断。部署必须限制后端网络入口，不能把可伪造的头或本机地址当作身份认证。设置 TLS 代理信任却没有可信连接地址时，配置直接失败。

发现并复现的问题是：IP 限流原先检查可信代理，但 Django 全局 HTTPS 转发头未检查连接来源，并会接受逗号列表的首项。新增五种来源/协议组合；修复前其中三个场景错误地返回 200，修复后正确重定向或允许可信 HTTPS。实际 Gunicorn 验证还覆盖不可信连接同时提供 X-Forwarded-Proto 和 X-Forwarded-SSL 的情况。

部署验证使用固定摘要的 Caddy、真实生产 Gunicorn、一次性 PostgreSQL 和真实 WASI worker。owner 只用于准备，Web 对内容/健康只读，worker 只有题目版本、任务和健康的必要权限。使用临时私有 CA，不修改系统信任；Python 客户端实际验证证书链、主机名和 TLS，错误 CA 触发证书验证错误，未知 SNI 被服务器拒绝握手。浏览器仅对临时 leaf SPKI 设置例外，专门检查 HSTS、Secure cookie、CSRF 和完整练习流程。该例外不用于部署配置。

同一实例记录浏览延迟、六账号实际判题的排队/执行/总耗时，以及 worker 停止后的拒绝入队和内容/草稿降级。结果、样本量、环境和清理成功状态进入机器可读摘要；检查失败不会留下成功摘要。测试通过不外推为大规模并发、恶意负载或公网可用性保证。

取舍：不为测试申请公网域名或安装私有根证书；这保留了可独立重放、低干扰的验收环境，但不能证明 ACME 签发/续期、远程数据库 TLS、生产 cgroup/systemd、自动部署或运维政策。工作流已定义，服务端 CI 尚未运行。具体数据和剩余门槛统一见[验收记录](../acceptance.md)。
