# ADR-051：容器任务的完整内核调用

日期：2026-10-31。状态：非 GPU 验证通过，完整 GPU 路径待验收。背景见 [RFC-021](../rfcs/021-gpu-container-supervision.md)，结果与边界见 [G35 验收](../acceptance-g35.md)。

新增 `KernelTask`，只接受原可信控制容器、同一 journal 和完整 v4 设备观察来源。任务使用 G34 的单卡镜像、设备配置和 journal v3；原无设备镜像不能经此接口执行内核。启动阶段只允许准备消息，核对设备、驱动、运行时与总预算，开始回调和原记录复核成功后才发送源码与受保护题目。

任务内的可信程序复用 `evaluate_kernel`，通过同一有界 guest 协议进行编译、数值比较与控制器计时。guest 只收到源码、操作和输入；保护答案留在可信程序中。共有题目/结果校验迁到 `gpu_task_protocol.py`，固定正确内核的恢复逻辑迁到 `gpu_recovery_kernel.py`，原宿主模块保留导入兼容和原协议。

任务 guest 必须停止，再在新的 guest 中编译和运行固定正确内核；恢复答案不匹配、未清理、通道断开、预算不足或平台错误均扣留结果。收到完整结果后，外部可信控制端还须关闭连接、按原记录移除外层任务、重新观察设备空闲，并确认源码身份没有变化。这个组件不发布 ready、不释放数据库预约，也不生成正式环境或 receipt。

执行预算继续为原整容器配置，覆盖监督器和运行时开销。任务预留独立恢复与清理时间；不能因学员超时耗尽恢复期限，也不通过放宽 seccomp、改成普通容器或重置设备完成恢复。

真实 CPU 取消场景发现，连接状态回调也会中断 runsc 清理。清理命令因此使用创建时保存的原硬期限，独立于通信与执行回调；仅允许列出状态、检查原 guest 或删除原 guest，不允许启动新任务或认领未知 ID。工作期限缩短或连接中断不能延长清理期限，也不能阻止对已知对象的终止。

当前设备接入授权待确认，G34 的只读设备绑定修复尚未实测。无设备验证用独立 CPU 服务和固定协议夹具，源码只作为不执行的数据；夹具入口、镜像契约和准备身份均不能通过 `KernelTask` 的 GPU 身份核对。CPU 的协议、计时字段和清理证据不证明 CUDA、显存隔离或真实性能。完整启动检查、正式环境、worker、Compose/发布及硬件验收仍需接通和验证。
