# ADR-052：容器 GPU 环境与任务结算

日期：2026-10-31。状态：已实现并通过非 GPU 验证；完整启动与硬件路径待验收。背景见 [RFC-021](../rfcs/021-gpu-container-supervision.md)，结果见 [G36](../acceptance-g36.md)。

容器任务使用独立的 `gvisor-gpu-container` 环境，由 `judge/container_environment.py` 定义。它固定完整设备与驱动/管理清单、不可变任务镜像、控制器/任务/运行时源码、Docker CLI/引擎/内核、NVRTC/runsc、会话与计时规则，以及包括监督器在内的整任务预算。控制器自身预算另行记录；不将整容器 512 MiB 配额描述为 guest 独占配额或显存限额。

`ContainerGPUAdapter` 接受原 `ContainerController`，通过 G35 的 `KernelTask` 调用编译、计算、独立正确恢复与清理。在开始回调后、发送源码前重验环境；完成后再核对结果制品、当前环境和租约。执行与取消沿同一任务对象清理，拒绝根据替换后的 journal 重建对象。`core/gpu_execution.py` 将成功结果交给已有 `GPUJobControl` 的短事务，继续使用原任务、整卡预约、私有成绩和学习证据。

历史成绩按保存的版本、字段和完整摘要校验，不要求旧策略等于当前源码。旧宿主环境格式保持不变；两个后端的环境摘要不同，不能混入同一环境榜单。结果页只显示经校验的设备、驱动、会话规则与摘要，不把驱动清单或管理细节扩展到公开分享。

控制镜像必须包含全部 `EXECUTION_SOURCES`，直接从镜像内文件计算完整策略，而不能使用宿主预计算值或漏项的源码快照。原无设备控制器检查增加镜像内策略与实际引擎身份核对；该检查不创建 GPU 环境、调用设备或连接产品数据库。

此增量尚未接通容器专用的完整启动、资源与故障检查。现有 receipt 入口继续只接受已实现完整启动的宿主适配器，网页准入继续拒绝容器环境；命令、Compose 与发布入口不会因为能够结算记录而自动启用新路径。测试中的合成环境和执行器只验证状态与数据规则，不能作为 GPU 就绪证明。
