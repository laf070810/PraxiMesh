# ADR-008：维护窗口发布与保留数据的恢复

状态：接受，2026-10-23；真实五代发布、失败迁移与中断恢复验收通过。设计：[RFC-005](../rfcs/005-deployment-coordination.md)。

单主机发布使用维护窗口。每代 Web 和 WASI worker 来自同一不可变制品，使用独立 PostgreSQL 代际库。先暂停并排空任务，再切维护页、停止旧进程、撤销运行角色连接并拒绝未知会话。冻结旧库的备份恢复到候选库，实际比较全部表行、列定义和序列状态，再迁移和验证候选。初始内容仅在第一次显式导入，升级保留已有内容和历史。

不直接迁移唯一在线数据库，也不假设任何迁移都有可靠的逆向操作。候选数据库使迁移、启动或实际功能检查失败时仍有原数据可恢复；代价是停机、复制时间和额外磁盘。当前实现限制在 PostgreSQL 17、普通带主键表和有界数据量；不承诺大规模、分布式或零停机发布。

部署 journal 原子持久化，同一目录使用文件锁，同一 PostgreSQL 实例标识使用会话 advisory lock。数据库及角色标记还绑定随机站点身份，其他状态目录不能重置同名角色凭证。一次性管理容器和复制工具均有独立执行期限；失败或中断不解除评测暂停。所有定时写维护也经过协调器锁。

每次启动候选 worker 均重新运行隔离探针。验证只接受指定 worker 在本次容器启动之后的新鲜心跳，并在暂停期间实际运行正确/错误提交，核对制品、策略与执行主机。合成测试数据按操作 token 和 worker 身份确定归属；恢复只清理完整匹配的私有测试记录，未知碰撞拒绝删除。

代理使用专用 Caddy 和私有 Unix 管理 socket，校验当前配置及进程用户后进行有条件的配置更新。重启配置也持久化；Caddy 被杀后只允许清除已确认无监听进程、归属和 inode 未变的陈旧 socket。不会占用共享 TCP 管理接口或修改系统证书信任。

在任何代理配置可能指向候选之前，journal 必须先保存 `exposure_target`。开放意图落盘以后，即使 reload 返回不确定，恢复也保留该数据库；不自动切回旧快照。这样已经发生的用户写入和删除不会被发布回退抹掉。开放以前的失败可恢复原代，但仍需重新运行实际候选检查。

保留的旧库和备份不是长期备份政策。异机灾难恢复、历史数据保留、目标主机监管、公有证书和生产容量须在目标站点配置并验证。代码不会自动推送镜像或创建公网实例。
