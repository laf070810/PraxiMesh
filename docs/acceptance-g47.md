# G47：GPU worker 生命周期与协调器中断恢复

日期：2026-11-01。对应 PRD R-09、R-16；[设计](rfcs/022-gpu-release-coordination.md)、[决策](adr/063-durable-gpu-worker-lifecycle.md)、[集中检查入口](deployment/container-gpu-worker.md#worker-lifecycle)。本轮使用自有临时文件、CPU 子进程和显式 Docker 测试模型，没有调用实际 Docker、加载镜像、查询或映射设备，也未重建现有服务。

## 实现范围

新增协调器内部的固定无设备预检及 worker 创建、启动、停止与重试。创建前持久记录原代、配置、内部网络、镜像契约和专用意图，核验后登记完整容器 ID；已登记对象丢失或同名替代均不重新认领。启动要求原维护路由、数据库操作锁、同 token 暂停和本代预检，先保存启动意图，再释放设备锁让 worker 取得。运行状态必须对应同一启动实例；提前退出、暂停或处于重启状态均不能当作成功。

停止沿原 ID、完整运行契约及启动时间确认，不抢 worker 的设备锁、不持队列行锁等待退出，也不删除任务记录或释放物理预约。停止结果观察失败时保留原意图并允许同实例重试。配置发布同时检查预检和 worker 的生命周期记录，未确认的创建、启动或停止不能绕过。

控制命令使用原 socket、空临时 Docker 客户端配置和限定环境，数据库凭证只保留在私有配置。预检不挂 socket、procfs 或设备；正式 worker 的固定映射仅在本轮测试模型中构造，没有实际执行。组件不签发 receipt、开放提交或宣称 GPU 就绪。

## 结果与证据

最终相关回归 **666 passed、4 skipped**，见 `test-results/g47-components.xml` 与 `.log`。四项 PostgreSQL 专项在当前 SQLite 环境中跳过，不算通过；包括新增的保留预约时暂停检查及连接释放检查。原有 CPU 发布、配置发布、GPU 入口和旧制品读取路径包含在此次回归中。

新增生命周期检查包含 **10 次实际协调器 SIGKILL**，分别覆盖持久创建意图、创建响应后、ID 登记后、启动意图、启动响应后、运行确认后、停止意图、停止响应后、停止确认后及预检完成后。恢复复用原私有目录、文件锁和持久测试模型，确认同一容器身份与意图，不重复已完成的创建、启动和停止。文件锁和被终止的 CPU 进程是真实的，Docker 结果、数据库与代理状态为显式模型；这不证明实际 daemon 或 GPU 生命周期成功。

测试还覆盖设备锁交接、未知同名对象、已登记对象丢失、错误预检、超时后继续同一预检、固定资源/挂载/环境变化、原暂停或维护条件丢失、停止失败保留原任务记录及预约。命令包装器检查原 socket、空客户端目录、限定环境、停止期限和错误输出脱敏，未调用实际 Docker。

原始失败与后续结果分别保留：

- `g47-runtime-initial.xml/.log`：测试模型误用设备锁的释放接口，2 failed、19 passed、2 errors；修正夹具后继续验证。
- `g47-run-state-before.xml/.log`：两项实际失败证明同一启动时间下的暂停/重启中状态会被接受；补齐严格运行状态核对后通过。
- `g47-lifecycle.xml/.log` 的 92 项和 `g47-core.xml/.log` 的 130 项为中间回归，已包含在最终检查中，不累计为独立检查数。

旧 F 与 G42 归档的本轮只读核验见 `test-results/g47-old-archives.json`；未导入或执行。源码身份见 `test-results/g47-policy-identity.json`。CPU 策略及 GPU execution/controller 源码与父提交 `e8f64cb` 相同；数据库部署辅助代码改变 worker 源码契约，实际使用须重新构建并验证匹配制品。

## 尚未完成

实际 Docker 的创建/启动/停止契约和镜像入口、PostgreSQL 暂停及锁竞争尚未在本轮执行。完整 GPU 启动、任务清理、就绪、队列、升级回滚和曝光后的恢复仍待接入与真实验收。`apply` 继续拒绝 GPU 激活，正式题目与提交入口保持原门槛。

此前恢复旧测试镜像被自动审批拒绝，相关许可仍未收到；本轮没有重试镜像加载或启动数据库。因此 [G44](acceptance-g44.md) 的实际 Web 恢复和完整 CPU 发布复验仍未完成。完整 GPU、托管 CI/runner、长期部署目标及运营授权按[需求追踪](requirements.md)保留。
