# G36：容器环境身份与任务结算

2026-10-31。容器 GPU 适配器接入已有任务结算与私有历史证据，使用独立、版本化的环境身份。设计见 [ADR-052](adr/052-container-gpu-environment.md)、[RFC-021](rfcs/021-gpu-container-supervision.md)。本轮按维护者要求不查询、映射或使用 GPU；容器完整启动、worker 部署与硬件验收仍未完成。

## 实现与验证范围

`ContainerGPUAdapter` 创建原 `KernelTask`，在开始事务后、源码发送前再次核对环境，完成后核对制品、当前配置与租约。任务必须先完成 G35 的独立正确恢复、内外层清理及空闲观察，才进入已有 `GPUJobControl` 结算。异常清理沿同一个任务对象执行；不能根据被替换的持久记录重新认领任务，清理失败也不会释放预约。

新环境绑定不可变任务镜像、单卡配置、驱动/管理清单、Docker 引擎与内核、控制器和运行时源码、NVRTC/runsc、会话计时规则与整任务预算。任务的 0.5 CPU、512 MiB、无 swap、256 个任务包括监督器；可信控制器另有自己的预算。旧宿主环境保持原格式，历史验证只检查保存的版本与完整摘要，不拿当前源码覆盖旧身份。两类环境不能混榜；结果页面使用经验证的环境说明。

控制镜像携带完整 `EXECUTION_SOURCES`，在镜像内计算执行策略，避免依赖宿主预计算值或缺文件的源码副本。现有 receipt 与网页准入明确拒绝尚未完成启动检查的容器适配器/环境；本增量没有新 worker 命令或 Compose 开关。

- **823 项组件检查通过，无跳过**：环境变更、开始回调前后拒绝、原任务清理、结果扣留、历史记录与学习证据、现有宿主兼容、容器与发布边界。记录为 `test-results/g36-components-final.log`、`.xml`。设备观察和内核执行使用明确的替身，不是硬件成绩。此前 143、186 项定向结果为重叠范围，不累加。
- **214 项实际 PostgreSQL 检查通过，无跳过**：新容器结果结算、账户删除、租约与预约保留，以及现有启动、就绪、worker、权限和持久恢复。记录为 `g36-postgres.log`、`.xml`。数据库和文件锁为真实执行，GPU 运行使用替身；一次性数据库容器与卷由原入口清理。随后增加的环境标签显示另由最终组件检查覆盖。
- **七组真实无设备容器检查通过**：原 UID 映射、双向锁竞争、错误用户/挂载拒绝及三种跨控制器接管保持通过；新增镜像内完整策略摘要和实际 Docker 引擎身份核对。报告为 `px-container-controller-30803a4f7a03/result.json`，日志为 `g36-controller-cpu.log`。该检查未启用设备观察，不构造 GPU 就绪环境。

只读收尾报告 `g36-audit.json` 确认 15 个自有容器、2 个镜像标签及 3 组原进程身份均已清理，临时存储已移除，实际控制镜像报告的源码摘要与当前文件一致。既有 Web、WASI worker 和 CPU 辅导服务均健康，本次未重建或重启这些服务。

最终 Ruff、格式和差异检查通过；新增文档后重放 36 项发布兼容检查全部通过，无跳过，日志为 `g36-release-delivery.log`。九份相关文档的 424 个本地链接与章节锚点通过核对，记录为 `g36-docs.json`。

## 原始失败与 CPU 复验

首次新结算测试使用了仅供调度的最小题目夹具，历史学习聚合缺少题目字段而失败：`g36-adapter-components.log` 为 1 failed、58 passed。改用完整的版本夹具后，同时验证本人完成记录与其他用户不可见；后续相关检查通过，没有削弱生产校验。

`judge/backends.py` 增加容器环境标签，改变了共同 CPU/WASI 策略。首次真实检查误选早期 `var/wasi-functions-b2`，在 `agent/correct` 因单轮限额超时，未生成 receipt；原日志保留在 `g36-wasi.log`。该制品缺少当前构建生成的标准库字节码缓存，与 [G10](acceptance-g10.md#策略身份与范围)记录的原因一致。当前构建产物的清单摘要、标准库缓存及相同固定 Agent 正确解另作定向核对，记录为 `g36-wasi-diagnosis.json`；保留题目原预算，不改写旧制品。

定向检查再次复现旧制品的 `time_limit`，同一正确解在当前制品获得 `accepted`。当前可信 bundle 来自此前真实 Compose 构建，清单摘要为 `ad9edfbe0cc8a4996789175f8fcb42feee618c8b4b21a8618858f5bf1fdd595d`；静态复核其标准库包含 558 个字节码文件，旧制品为零。随后使用当前源码执行完整 **129 个真实 WASI 探针，全部通过**，日志为 `g36-wasi-final.log`。新 receipt 由真实入口生成并经原校验函数核对，绑定本轮 CPU 策略和完整检查集，权限为 0600；核对记录为 `g36-wasi-audit.json`。没有复用旧凭证或改变现有服务，结果只证明本次宿主 CPU/WASI 路径。
