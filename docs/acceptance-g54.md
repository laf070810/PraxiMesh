# G54：GPU 曝光决定与中断后的原库保留

日期：2026-11-02。对应 PRD R-09/16；[设计](rfcs/022-gpu-release-coordination.md)、[决策](adr/070-durable-gpu-exposure-decision.md)、[集中入口](deployment/container-gpu-worker.md#durable-exposure)。本轮没有实际 Docker、PostgreSQL 或 GPU 操作，没有改动既有站点服务。

## 已实现

内部曝光连接已完成的候选准备、持久数据库决定、恢复准入、代理切换和外部 CPU/GPU 健康检查。决定在恢复准入之前落盘，绑定原操作、完整发布代、冻结归档、验证轮次、原启动/owner/配置/环境及 Web 端口。恢复准入或代理响应丢失时，重试观察实际状态，不重复提交候选测试或重启 worker，也不回到旧数据库。

开放后的合法用户任务可以继续排队、运行。只读数据库快照核对原实例和新鲜性，并复用冻结应用的正式准入规则检查兼容任务、租约及预算；最终外部健康同时要求 CPU/GPU available。观察本身不释放预约或清理数据，普通准备与启停仍要求原暂停和维护路由。已开放后再次暂停/撤回路由须走原库恢复；完成新启动验证后建立新曝光记录，保留历史及当前库。

公共 GPU 激活和恢复拒绝仍生效。完整 apply、曝光前失败回退、曝光后整站恢复入口及 GPU→CPU 尚未完全连接，不能据内部流程声称整站 GPU 部署已交付。

## 验证范围

最终 `test-results/g54-components-final.xml/.log`：**708 passed、14 skipped**。包括候选准备/轮次、曝光、原库恢复、配置发布、worker/就绪、冻结、原 CPU 发布、Web 恢复和制品校验。14 项跳过均为实际 PostgreSQL 专项：7 项配置/快照、5 项冻结、2 项候选事务；不计为通过。下方子集与最终结果不累计。

首轮 `test-results/g54-exposure-initial.xml/.log` 为 106 passed。随后按实际数据库字段核对预约，`g54-reservation-before.xml/.log` 复现了两项错误：有效 UUID 任务被拒绝，而整数任务 ID 可能被接受；修正后使用真实字段形状，正式租约/预算仍由应用准入校验。该失败记录保留，不能把最初的整数测试模型当作真实数据库通过。

`g54-exposure-components.xml/.log` 为 166 passed、7 skipped，覆盖曝光、只读快照、健康响应和原 worker/就绪保护。7 项实际 PostgreSQL 检查因 SQLite 环境跳过，其中新增一项开放准入、UUID 预约保留及外来暂停拒绝。测试没有连接 PostgreSQL，也不计跳过为通过。

实际执行私有文件、文件锁、冻结源码读取和 CPU 子进程 SIGKILL；Docker、代理、数据库、设备环境、正式成绩与用户写入为明确的测试模型。七处曝光中断点覆盖决定落盘、恢复准入但未确认、resumed、activating、代理切换但未确认、外部健康完成及最终 active 落盘。父进程核对信号并回收自有子进程，重试保留原启动和用户写入模型，不再执行 GPU 测试提交。

边界检查包括未完成/丢失准备、错误轮次和归档、CPU/GPU 就绪失效、错库/目标/路由/端口、owner/启动改变、异常或过期快照、不兼容任务和预约、非布尔可用标志、损坏日志、再次暂停及撤回路由。恢复后新轮曝光同时覆盖 active 和 rolled_back 结尾；旧记录与当前数据库保持不变。慢环境观察须在最终身份核对后再次检查心跳，不能沿用检查前的新鲜性。
