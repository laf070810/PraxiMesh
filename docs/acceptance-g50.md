# G50：GPU 候选队列检查与原任务清理

日期：2026-11-02。对应 PRD R-09、R-16；[设计](rfcs/022-gpu-release-coordination.md)、[决策](adr/066-gpu-candidate-queue-verification.md)、[集中检查入口](deployment/container-gpu-worker.md#candidate-verification)。本轮不调用实际 Docker、不启动 PostgreSQL、不查询或使用 GPU，也不更改既有站点服务。

## 实现与验证边界

新增内部 GPU 候选检查，固定向量加法和减法错解经正常 `enqueue` 创建两个正式 Submit。检查要求本次暂停、指定 CPU/GPU worker、单卡、原启动、设备 owner 与完整冻结环境一致；在同一事务中完成临时准入、提交及重新暂停，不提供生产替身、跳过准入或宿主执行选项。

稳定操作标识绑定无密码账号、临时题目版本及原提交。超时保留原记录和预约，480 秒观察期限从最早提交计算；未知关联数据或来源、版本、预算不匹配时不清理。成绩检查复用正式证据校验；正确/错误结果、通过数、性能契约、时间与环境必须符合预期，全部队列及所有设备预约均须排空。

检查通过后仍保留原提交，协调器先持久保存成绩响应，再执行独立清理并保存清理响应。确认丢失时重读原成绩；清理响应丢失只重试清理，不重新创建任务。五个持久阶段为 checking、checked、cleaning、verified、cleaned。清理观察继续绑定原容器、配置和环境；成功阶段也重新检查就绪，不是曝光凭证。原 worker 重启后，只能按新鲜身份清理旧测试记录，不能用旧成绩验证新启动。

最终相关回归 **935 passed、22 skipped**，见 `test-results/g50-final-components.xml/.log`。测试实际使用一次性 SQLite 数据库、私有文件、文件锁、源码归档和协调器 CPU 子进程；设备环境、GPU 成绩、Docker、代理及协调器 PostgreSQL 状态为显式模型。数据库模型不签发实际 receipt，也不证明 CUDA、计时、物理恢复或部署成功。

## 关键结果

- 数据库检查覆盖：原暂停与身份、原提交重复观察、完整正式证据、其他用户及未知关联数据保留、事务失败整体回滚、原预约和其他设备孤立预约保留、过期观察与失败清理。校验命令直接返回通过不表示已经清理；测试分别验证这两个结果。
- 五处实际协调器 SIGKILL 后从原私有文件继续，包含成绩已确认但尚未清理的位置；父进程确认终止信号并回收自有子进程。另有清理已完成但响应丢失的场景，只再次调用 cleanup。容器与管理命令在这些测试中为模型。
- 冻结命令协议、完整响应的字段/类型、原代/启动和配置发布门槛保持拒绝；成功响应之后失去就绪也不保存完成。Web/管理环境只获得绑定设备的准入名单，CPU worker 环境不增加 GPU 设置。
- `g50-boundary-regression.xml/.log` 保留三项修复前失败：过期观察仍接受晚到成绩、未知任务状态被当作终态清理、非字典环境未作为命令错误拒绝。修复后均包含在最终回归中。
- `g50-ack-before.xml/.log` 保留成功响应尚未持久确认时原提交已经删除的一项失败；改为先确认、再清理。`g50-cleanup-binding-before.xml/.log` 保留两项清理观察身份损坏仍被配置发布接受的失败；补齐原容器和配置绑定。

早期 `g50-coordinator-initial` 的三项失败是环境测试夹具缺少代理路径；`g50-boundary-before` 的过期用例先被正确的启动时间检查拒绝，调整夹具后另行保留真正的过期失败。`g50-ack-fixed` 的 26 项失败来自清理条件补丁落在错误分支，静态检查同时发现了未定义变量；修正后 `g50-ack-final` 的 148 项检查通过。`g50-core` 的 197 passed、2 skipped 和确认窗口修复前 `g50-components` 的 930 passed、22 skipped 均为中间记录，与最终检查重叠，不累计计数。

22 项实际 PostgreSQL 专项在当前 SQLite 环境跳过，包括原有的角色/权限及锁检查，以及新增的公共暂停不可见窗口、等待期间心跳可写检查；跳过不算通过。该入口须在获准的一次性数据库中另外执行。

旧制品只读核验通过，见 `test-results/g50-old-archives.json`：F 清单 `896e1c1b605025376ed30786ea4e79d3fde008c97e7d114bf91febd86cc62482` 的 464 个源码文件、两个镜像；G42 清单 `44b6ca03b1e22d92382e5a04b578dee64813f57eceb1b3c3485117b0fdfa2142` 的 839 个源码文件、四个镜像及完整层。本轮没有加载镜像或执行归档代码。

源码身份见 `test-results/g50-policy-identity.json`，父提交为 `3a5aaac`。CPU 策略及 GPU execution/controller 源码范围保持不变；新增两份应用源码进入 worker 范围，改变 worker 契约，实际部署须构建匹配的新制品。旧归档可核验，不等于支持新检查命令。

全仓库 Ruff 静态与格式检查通过，宿主协调器组件在没有 Django 配置时可独立导入。9 份相关文档的 444 个本地链接核对通过，结果见 `test-results/g50-docs.json`；部署操作继续集中维护。
