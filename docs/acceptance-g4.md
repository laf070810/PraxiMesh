# G4：GPU 交互执行与计时实现进度

日期：2026-10-30。**实现已加入，真实 GPU 验收未完成，网站 GPU 提交继续关闭。** 设计见 [RFC-019](rfcs/019-gpu-kernel-evaluation.md)及 [ADR-019](adr/019-gpu-session-protocol.md)。操作入口统一在 [GPU 指南](deployment/gpu.md#交互执行与批次计时检查待真实验收)。

## 实现

- 非阻塞、逐条请求的 CUDA 会话；编译架构核对，严格 JSON 帧与输入/输出上限，编译、请求和会话期限，取消回调与自有容器清理。
- 受信控制器比较所有答案；公开 Run 只执行公开用例。正式模式只有正确性和采样都通过才保留控制器批次时间，隐藏名称和结果不返回。
- 固定 16 次批量调用、2 批预热与 5 批测量；每次调用重置输出并同步，驱动不产生计时或分数字段。
- 新 `--session-probes` 复用同一实现，包含最大向量/矩阵、错误分类、输出超限、取消和附着客户端异常退出后的清理及恢复。所有探针模式共用每卡主机锁，锁文件按设计保留。

## 已完成的非 GPU 检查

`test-results/g4-session-initial.xml` 为 78 passed。补充严格批次数、独立模式时限、重复控制器拒绝及 OOM 分类证据要求后，`g4-components-final.xml` 为 104 passed、8 skipped。提交前复核发现两个最大合法数组的小数编码需要 200746 字节，超过原 128 KiB 帧上限；已统一控制器/驱动为 256 KiB，增加向量和矩阵的真实管道传输回归。最终 `g4-components-commit.xml` 为 **106 passed、8 skipped**；8 项跳过均为 PostgreSQL 专属场景，其既有预约/租约证据仍属于 G3，本轮未重复该矩阵。

会话测试使用固定的本机管道助手返回预定帧，不编译或执行传入源码。它证明重复键、错误架构、伪造时间、额外输出、编译超时、取消和清理失败会被处理；不证明 CUDA 正确性、实际限额、GPU 回收或性能。Ruff、格式及差异检查通过，CLI 帮助与文档参数已核对。

## 真实重放未执行的原因

`test-results/g4-sessions-first.log` 记录目标卡已有计算任务，程序在创建临时服务、容器和 GPU 工作负载前退出。只读复查确认是另一个 UID 的 Python 进程；没有终止该进程，也没有改用其他显卡。维护者随后要求先继续不占 GPU 的开发。

因此本轮没有 GPU 时间样本、成功 receipt 或新的硬件通过结论。G1/G2 是各自记录源码版本的历史证据；本轮修改了共用探针启动路径和驱动批次逻辑，不能直接沿用其结果证明新代码。现有 CPU 评测器及其策略源码范围未改动。

## 后续门槛

在独占条件恢复后重放会话模式和受影响的原有模式，确认真实输入边界、OOM/输出/时间上限、取消、客户端退出与设备恢复；还需每任务硬期限、外部占用监测、不可复用的启动记录、正式 worker/队列/内容/页面和可比性证据。当前执行摘要和单元检查均不能替代这些门槛。
