# G37：容器内固定内核启动检查

2026-10-31。将原十九项固定 CUDA 检查接入容器维护协议和执行适配器，新增独立的嵌套 guest 清理报告。设计见 [ADR-053](adr/053-container-kernel-startup-checks.md)、[RFC-021](rfcs/021-gpu-container-supervision.md)；操作集中在[无设备调用链检查](deployment/gpu.md#container-kernel-flow)。本轮不查询、映射或使用真实 GPU。

## 实现与检查边界

维护请求只携带固定名称及随机挑战，可信任务端从既有目录生成源码与保护答案。普通任务目的不能发起检查，也不能替换检查源码。保留原执行预算中的独立恢复与清理时间；报告等待新的正确 guest、内外层清理和最终空闲观察后返回，不产生学员成绩或就绪凭证。

内层 runsc 的私有标签使用 `container-kernel-check-v1` 报告。原状态、原附着进程返回码、进程树消失和状态移除全部核对后保存首次清理证据，重复清理保持原观察。宿主 Podman 报告继续校验其完整容器 ID；两条路径共享预期判定、编译完成、计时及故障规则。模块内存错误仍须观察退出码 4；取消和附着退出增加独立的中断前原 guest/附着进程活跃观察，并要求中断后完整清理。

- **最终 1,010 项相关回归通过，无跳过**：覆盖十九项固定规则、新报告的挑战/身份/布尔值/缺项拒绝、中断前实际观察接口、原任务目的与清理、环境适配、已有宿主启动/worker/准入/历史和发布兼容。记录为 `test-results/g37-components-final.log`、`.xml`。设备和 CUDA 路径为明确替身，不是硬件结果。
- **十六项真实 CPU/runsc 场景通过**：原十项调用、错误分类、取消、独立恢复与新调用，以及六项新增命名正确解/错解、编译后取消/附着退出、非预期结果和恢复失败场景。报告为 `px-container-kernel-439204b990b1/result.json`，日志为 `g37-kernel-cpu-observed.log`。两项中断都实测到触发前原 guest 为 running、附着进程活跃；清理时 guest 已停止，原附着返回码为 -9，随后正确恢复和原外层清理通过。
- **七组真实无设备控制镜像检查通过**：UID 映射、共用锁、错误用户/挂载拒绝、跨控制器及宿主双向接管，以及镜像内完整策略计算。报告为 `px-container-controller-4cd67009b951/result.json`，日志为 `g37-controller-cpu.log`。没有启用设备观察或连接应用数据库。
- 更早的 229、992 项回归、入口修复后的 103 项专项及中断观察修复后的 250 项检查分别保留在 `g37-components-initial`、`g37-components`、`g37-entry-fixed`、`g37-interruption-fixed` 的日志和 JUnit 中。这些是重叠范围，不与最终结果累加。

只读收尾审计 `g37-audit.json` 确认三轮内核调用及控制镜像检查的 **53 个自有容器、5 个镜像标签、41 组原进程身份**均已清理，临时存储已移除。最终通过报告的源码摘要与当前文件一致；原失败报告保留各自原身份。既有 Web、WASI worker 和 CPU 辅导服务均健康。Ruff、633 文件格式检查和差异检查通过；最终组件矩阵包含 36 项发布兼容检查，新增文档后的独立记录为 `g37-release.log`、`.xml`。九份文档的本地链接与章节锚点已核对，记录为 `g37-docs.json`。

CPU 程序只计算固定向量数据，不编译或执行收到的 CUDA 源码；其检查结果和计时字段只验证控制逻辑，不能替代十九项 CUDA 的正确性、性能或设备恢复验收。

## 原始失败与修正

首次真实 CPU 矩阵在九个原有场景通过后，进入第一个命名检查时由普通任务构造器拒绝 `check-public-run` 模式，未发送维护请求。报告为 `test-results/px-container-kernel-ee320920e0bf/result.json`，日志为 `g37-kernel-cpu-initial.log`。失败场景的容器按原 journal 停止并移除，临时存储和镜像标签已清理，未把部分通过当作完整通过。

修复将请求构造集中到 `request_for`：普通任务、维护恢复和固定检查分别使用其已有协议，在创建容器前完成构造；非法请求场景仍保留原预期拒绝。补充八种实际入口模式检查后重放完整矩阵，没有改动生产准入或放宽协议。

第二次真实重放在命名正确解和错解通过后，取消场景因清理前运行状态断言失败。报告为 `px-container-kernel-b96c9c1bbfbb/result.json`，日志为 `g37-kernel-cpu-final.log`；该文件名不表示整体通过。实际嵌套 runsc 在关闭附着进程后已观察到 guest 停止，原宿主断言不能直接代表中断时是否活跃。修复增加触发前的原状态与附着进程观察，保留事后停止/移除及进程树清空确认，再独立运行正确恢复。宿主原清理断言保持不变；缺少任一观察或提前退出仍拒绝。原失败容器及存储均按原记录清理。
