# 内容规范与贡献审核

当前格式：`content/schema.json`（版本 1），完整示例：`content/starter.json`。内容作为数据加载，不执行参考代码或动态插件。`content_check` 是结构检查，**不是解法通过证明**。

## 知识组织

稳定 ID 使用小写 ASCII slug，不因标题、翻译或归属变化改 ID。Domain/Topic 表示导航，Concept 可关联多个领域/主题；tutorial 引用概念；path 用显式 steps 引用教程或题目。抽象概念避免语言前缀；题目声明 Python。required 关系表示必要前置，recommended 表示建议，related 表示横向关联。只检查 required 无环，相关关系允许环。重复、指向自身或同目标的矛盾关系禁止。

新增概念前搜索标题和 aliases。重复概念应先 RFC 讨论合并并保留旧 ID 的迁移，不直接删除身份或修改历史题目。标题/别名唯一性在同一包内检查。初版只显示中文；未来以同一 ID 增加 locale 数据，缺失译文回退中文并明确标记，不能靠复制概念翻译。

## 一道题的完整契约

必须有任务、输入/输出/约束、目标、知识点、难度、语言、函数名、起始代码、参考实现、提示、公开和受保护测试、比较规则、修订说明、署名和授权来源。测试至少四个，最多二十个；参数的 UTF-8 JSON 最多 100,000 字节，预期结果的 ASCII 转义 JSON 最多 32,000 字节，为实际协议预留空间。整个包最多 5 MB。至少覆盖普通输入、声明上限、关键边界和典型错误。数值题必须显式声明绝对/相对容差；NaN/Infinity 不允许。

`python-function-v1` 只支持 JSON 参数和 JSON 返回值。题页显示实际后端支持的标准库边界，无网络或第三方包。JSON 不表达 tuple、集合、自定义对象。`exact` 要求数值类型一致（布尔不等于整数）；`numeric` 允许 int/float 在容差内相等，仍检查形状、键和有限性。

公开页面通过字段白名单生成，不包含 reference、私有测试名称/输入/输出。受保护测试每次只向沙箱提供当前输入，控制器持有预期值。**示例包在源码仓库中可见，因此其测试不是对仓库读者保密的考试数据。** 部署时不要将内容目录配置成静态目录。真正需要保密的测试包应放在私有发布源，并另行评估泄露与作弊风险。

## 修订与发布

1. 修改 JSON 包，执行 `uv run python manage.py content_check path/to/package.json`。
2. 审核知识语义、关系、文字可独立理解性、许可来源；人工核对样例。不能凭 schema 通过就标记“已审核”。
3. 在隔离的测试 worker 上运行所有参考实现和典型错误变体。内容贡献同样不可信，不允许在 Web/CI 宿主直接 `exec(reference)`。
4. 维护者审核后运行 `content_import`。它是整个包的原子替换发布：缺失 ID 会下线，旧记录及题目版本保留。
5. 已存在的 `(problem_id, revision)` 不可修改；更新题意、测试、环境契约或参考实现都增加 revision 并写 changelog。历史提交保留旧版本数据和摘要。导入旧版本不能自动回滚当前版本。

路径进度统计当前版本的正式通过。公开样例运行不算完成；旧版本历史仍可查。撤回路径或题目不会删除历史。正式版权/许可和独立审核尚未完成前，内容包的 `LicenseRef-Pending-Maintainer-Approval` 表示内部开发状态，不能当作可再许可素材。
