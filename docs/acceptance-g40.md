# G40：容器完整启动与就绪发布

2026-10-31–2026-11-01。将容器初始恢复、完整检查、私有凭证、心跳/领取和取消恢复接入共同的数据库发布流程。设计见 [ADR-056](adr/056-container-complete-startup.md)、[RFC-021](rfcs/021-gpu-container-supervision.md)，验证入口集中在 [GPU 指南](deployment/gpu.md#container-startup)。本轮不查询、映射或占用 GPU。

## 实现与边界

容器初始恢复按原 journal 停止和归档，随后在新维护实例运行正确恢复；二十四阶段全部完成及私有凭证校验成功前保留原任务与预约。原实例清理、设备空闲、资源挑战、原 guest 报告、三种控制器故障的新恢复与完整环境均须匹配。

容器凭证采用独立 schema/套件，绑定真实宿主身份、映射操作者、原挂载、安装/daemon/锁目录与当前环境。发布仍使用既有私有文件和原子数据库事务。Web 只读当前完整环境和健康，领取端再次验证私有凭证。宿主路径保留原格式；容器不能接管仍有预约的宿主任务。

**184 项实际 PostgreSQL 检查通过，无跳过**，见 `g40-postgres.log` 和 `.xml`。包括容器二十四阶段顺序、不同任务实例、原预约保留、原记录归档、过期与跨所有者/挂载/安装拒绝，以及宿主兼容、发布与行锁竞争、Web 只读准入、领取和取消恢复。另以实际 `SET ROLE` 切换到现有 worker 的最小权限，宿主和容器完整启动各通过一项，见 `g40-postgres-worker-grants.log` 和 `.xml`；未扩大数据库权限。两个入口均确认自有临时 PostgreSQL 容器和卷已删除。

这些批次范围有重叠，不累加为唯一测试总数。GPU 方法在数据库测试中是明确的测试替身，临时序列化文档不能用于实际站点启动；不以这类测试证明 CUDA 正确性、性能或物理恢复。
