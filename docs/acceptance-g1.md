# G1：CUDA 内核契约与真实正确性基础

日期：2026-10-30。范围对应 [RFC-019](rfcs/019-gpu-kernel-evaluation.md)第一步。**这是评测组件验证，尚未交付 GPU 题目、网站提交或常驻 worker。** 操作命令集中在 [GPU 部署指南](deployment/gpu.md#重放内核正确性检查)。

## 实现与验证边界

`judge/gpu_contract.py` 定义有界 CUDA 源码、float32 向量加法和行主序矩阵乘法输入；公开投影去掉隐藏用例，执行请求只包含源码或输入。受保护答案由可信控制器保留并比较。固定 Driver API 驱动只在 gVisor 中通过 NVRTC 编译设备代码，不编译或执行学员宿主程序。

输入限制为向量最多 4096 元素、矩阵各维最多 64、每题 2–8 个公开/隐藏用例、源码最多 20,000 UTF-8 字节。输出逐次填充 NaN 哨兵，遗漏写入不能冒充正确结果。内核 `printf` 与协议输出分离；该机制仍须补充恶意输出的真实探针。性能计时、资源故障及队列预约不在本次通过范围。

## 原始失败与修复

原始临时脚本的结果保留在 `test-results/`，不覆盖失败记录：

- `px-gpu-cgns-33bd742b8947`：固定公开镜像拉取继承过期 Docker Hub 认证；改用本次临时目录的空认证文件，未改写用户凭证。
- `px-gpu-cgns-bb2349ac0a74`、`01a338b6b1f7`、`4a947da022df`：NVRTC 编译失败；受限私有诊断最终定位为 builtin 库加载问题。补齐官方库别名及 `/opt/nvrtc:/usr/lib64` 搜索路径后，`px-gpu-cgns-292d6faa6c47` 首次通过全部 7 组检查。
- 之后将临时实现整理为现有环境检查入口的可选内核模式，再得到上述 `a964bae7acdf` 成功结果。
- 厂商模式回归 `px-gpu-cgns-ce7b44f8eba9` 在镜像下载阶段超过 240 秒，未执行 GPU 程序，清理成功。仓库直连检查正常；仅为下一次命令移除继承的代理环境后，`2f7de749d002` 下载与全部检查通过。未修改主机或用户代理配置。

这些路径包含合成样例与诊断，未提交到 Git。正式学员结果不得回传原始编译器日志、隐藏输入或运行诊断。
