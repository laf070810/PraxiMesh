# 自部署版本威胁模型

修订：2026-10-24。WASI、PostgreSQL 最小权限与回环 HTTPS 已有真实验收；C 的实际验证见 [C 验收](acceptance-c.md)，D 挑战增量已通过 PG、HTTPS、固定镜像和 C→D 升级验证。gVisor、真实 GPU 和公开运营环境仍待验收。

| 资产/威胁 | 控制与边界 | 验证 |
| --- | --- | --- |
| 宿主、数据库、其他用户代码 | Web 不能执行代码或访问 Docker socket；专用 worker；每用例新 WASI 实例，只读标准库，无网络/业务环境变量；gVisor 为独立策略 | 真实沙箱网络、文件、环境、跨任务隔离探针 |
| CPU/内存/输出/磁盘耗尽 | 各评测契约固定线性内存、fuel、输出、驱动地址空间、CPU、墙钟与 FD 上限，无可写宿主目录；Python 基础函数及专门的完整程序/Agent 预算分别见 [WASI](deployment/wasi.md)、[完整程序](stdio-contract.md)和 [Agent](agent-contract.md) 契约；gVisor 保留 cgroup/ulimit 策略 | 真实死循环、内存、阻塞调用、输出、FD 与禁止写入/进程/线程探针 |
| 伪造评测通过 | 预期值只在控制器；沙箱返回普通 JSON 值；控制器比较全部选定测试 | 比较器、错误变体与真实正确解测试 |
| 私有测试泄露 | 白名单页面；隐藏用例输入/预期/输出/异常文本不回传；无网络；单用例输入不可避免可见 | Web projection 和结果脱敏测试 |
| 用户越权、XSS、CSRF | 每个草稿/提交/导出均按会话 user 过滤；模板默认转义；严格 CSP；CSRF；POST-only 修改 | 两账号越权、恶意源代码、CSRF 与方法测试 |
| 密码、恢复码和会话 | Django Argon2、一次性恢复码哈希、密码验证与轮换、生产 Secure/HttpOnly cookie、无第三方脚本 | 恢复码重复使用/旧会话失效测试 |
| 登录/注册/提交滥用 | 共享数据库的时间窗口限流；主体 HMAC；每用户 2 个活跃任务，全局 100；注册生产默认关 | 限流/队列测试；上线需反向代理全局连接和请求速率控制 |
| worker 崩溃、迟到结果 | 原子领取、租约 token、过期转 internal_error、条件写终态；不自动重复执行 | 租约抢占、终态不能被旧 worker 覆写；WASI 驱动 OS alarm 和父进程死亡 SIGKILL 已实测 |
| 内容/依赖供应链 | Schema/引用/DAG/不可变修订；JSON 无动态执行；依赖锁和 hash；漏洞审计；镜像/解释器/标准库/运行时摘要；受保护审核 | 内容测试、CI、真实参考解/变体检查 |
| 专业结果伪造、额度绕过 | ML 留出评分、独立科学拟合基准、Agent 真实工具轨迹；统一正式证据校验；事务内预约、有效租约消费、幂等请求和执行前失败释放 | 真参考/错解、严格结果结构、PostgreSQL 并发与 API 测试；不以客户端自报结果计分 |
| 组织越权与内容接管 | 定向邀请、本人接受、不可变课程修订、独立审核摘要；维护通道发布，官方与组织归属共用锁；Web 对正式内容只读 | 跨账号和角色检查、真实 PostgreSQL 最小权限、课程/包保留与删除测试 |
| 活动刷量与参与隐私 | 自愿加入，固定 UTC 窗口与题目版本；只查本人可信正式结果；退出重入不恢复旧进度；成就不自动公开 | 时间边界、跨账号、导出/删除、实际 PG 并发；定义表 Web 只读、worker 拒绝 |
| AI 外发、资源与响应注入 | 默认关闭；逐次预览确认，源码单独同意；固定 HTTPS 服务及私有凭证，仅 Web 可见；独立受限传输进程，硬截止、无工具、转义正文；原子日用量和独立执行租约 | 真实 HTTP/TLS 边界与进程回收、PG 竞争/执行中删除、关闭和真实模型浏览器；模型输出不写正式成绩 |

`judge/sandbox.py` 的 guest wrapper 不是隔离机制。用户可以覆盖模块、提前退出或伪造返回 JSON；运行必须全部留在所选的隔离边界中。WASI 不提供加载本机程序/原生扩展的能力；gVisor 中的系统调用留在独立容器边界内。wrapper 退出码只提供错误类别，不能授权通过。唯一可信的正确性结论来自外部比较器。错误分类可以被恶意程序伪造，但不会因此产生 Accepted。

gVisor 的配置名不能证明运行时二进制可信。安装由主机维护者从官方源完成，记录二进制版本/校验值，内核和 Docker 同时受维护。当前检查验证 runtime 注册、资源能力、有效容器配置及探针；不声称能够证明没有运行时漏洞、硬件侧信道或宿主管理员恶意行为。

`sandbox_check` 仅在所有真实探针完成（gVisor 还须确认没有遗留容器）后写 24 小时的本机检查记录。worker 检查对应镜像/运行时/策略和新鲜度，定期更新心跳；Web 仅向符合配置的活跃 worker 排队。执行异常或清理失败时 worker 停止接收任务，标记平台故障。本机已产出 WASI 检查记录；gVisor 仍因无 runsc/CPU quota 被拒绝。两者的通过记录不能互用。

WASI 固定解释器和标准库只读挂载；原生预编译 cache 属于可信制品，不接受用户上传。每次执行检查制品文件及 Wasmtime 动态库摘要，拒绝额外文件、符号链接、可被其他用户写入的目录和运行中库变更。Python SDK/Wasmtime 安全公告须持续跟进；检查不能证明不存在运行时漏洞或侧信道。

策略摘要覆盖两个执行器、结果比较器、队列、worker/探针代码和依赖锁。worker 心跳固定使用启动时的摘要，不将磁盘上后来修改的代码冒称为当前运行代码；部署必须使用不可变制品并重启 worker。被删除或失去租约的任务仅丢弃结果，不因用户删除账号而停掉其他人的 worker。

固定窗口限流存在跨窗口最多约两倍的瞬时突发；队列上限提供另一层边界。默认使用 REMOTE_ADDR，忽略客户端转发头；仅当连接来自显式配置的 TRUSTED_PROXY_IPS 时才接受代理覆盖的单个 X-Real-IP。HTTPS 转发头也在 Django 安全/CSRF 中间件之前检查连接来源，只接受单值 `http`/`https`，拒绝逗号列表；Gunicorn 不从其他头自行推断 scheme。代理必须无条件重写这些头，后端禁止绕过代理访问；示例配置使用直接连接代理的客户端地址，不解析任意 X-Forwarded-For 链。临时真实 HTTPS 部署已验证代理覆盖、未受信连接不能伪造 HTTPS，以及伪造 X-Real-IP 仍受同一限流桶约束。生产代理还应实施全局连接/请求限流。worker 的最小数据库角色已在隔离 PostgreSQL 实例验证；生产网络/身份边界仍需复验，不要让执行节点连接无关业务数据库。

数据最小化：不收邮箱或真实姓名；不记录源代码、测试输入、密码、恢复码到日志。恢复码在成功响应中显示一次，数据库只保留哈希。用户可导出和密码确认删除。运维备份也是私有数据，须加密、限权、按公布周期过期；恢复后要重新应用删除记录，尚未配置的生产保留政策是发布阻塞项。

所有公共发布仍需通过 [阶段门槛](plan.md)，并经过维护者独立安全审查。不能将绿色单元测试、普通容器能运行或一份检查 JSON 当作完整的公开安全证明。
