# G55：GPU 配置退出与后续发布

日期：2026-11-02。对应 PRD R-09/16；[设计](rfcs/022-gpu-release-coordination.md)、[决策](adr/071-durable-gpu-configuration-retirement.md)、[集中入口](deployment/container-gpu-worker.md#configuration-retirement)。未运行实际 Docker、PostgreSQL 或 GPU，没有修改既有站点。

## 已实现

为 GPU→CPU 及 GPU 候选失败后的 CPU 回退补充内部配置退出。退出前保存完整原代和原配置快照，要求实际维护路由、原设备锁、原库冻结、全部 worker 停止、空闲任务 journal、原暂停和排空保护。配置删除复用持久过渡标记，只移除精确匹配的 worker/代际两份文件；完成后 active=None，保留节点、锁、容器、数据库和验证历史。

中断继续同一退出意图，未知文件/临时文件和曝光决定均阻止删除。未完成退出阻止其他配置发布，底层删除也要求原记录和快照；完成不能作为下一代的退出许可。后续新操作可从无有效配置的状态发布新代，不再要求更改退休库的旧暂停 token。

这一步没有开放公共 GPU→CPU 或完整 GPU apply/recover，尚须继续连接整站发布、候选失败回退和曝光后恢复。模型、文件删除与中断检查不证明 CUDA、物理资源恢复或部署已成功。

## 验证范围

最终 `test-results/g55-components-final.xml/.log`：**739 passed、14 skipped**。覆盖配置退出、原有发布/准备/曝光/恢复/冻结、CPU 协调器、Web 恢复及制品校验。14 项实际 PostgreSQL 专项因 SQLite 环境跳过：7 项配置/快照、5 项冻结和 2 项候选事务，不计为通过；子集结果不与最终结果累计。

首轮 `test-results/g55-retirement-initial.xml/.log` 为 102 passed，覆盖退出、原配置发布及原代冻结。随后 `g55-origin-before.xml/.log` 保留两项复现：外层检查后原退出快照被替换，或提前改为完成状态时，底层删除仍可能继续。修正后底层再次绑定原快照和阶段，拒绝变动，原文件保留。

实际运行的是私有文件、原文件锁、fsync 与自有 CPU 子进程；Docker、数据库冻结/排空、代理和 GPU 环境为明确模型。八处 SIGKILL 分别覆盖退出意图、配置过渡意图、标记建立、两次文件删除、配置确认、标记移除和退出完成；父进程确认信号并回收子进程，再沿原记录完成退出。

检查还覆盖删除时同时持原设备/数据库保护、缺失退出意图、活跃 worker、未冻结库、残余工作、非维护路由、已曝光目标、未知 journal/临时文件、外来配置、错误服务名、损坏记录、确认丢失及新操作发布。新操作检查明确只访问新库的排空门槛，原库和原暂停保留。文件移除不产生 GPU receipt，也不清理实际任务或未知资源。

README 的能力和启动入口继续适用。本轮没有界面、内容、迁移、固定镜像或现有服务的变化。

Ruff、格式、无 Django 设置的模块导入和差异检查通过。`g55-identity-docs.json` 核对九份文档的 474 个本地链接、显式锚点唯一性及最终源码摘要；相对 `3d597f8`，CPU/GPU 执行策略、控制器和 worker 四项源码契约均未变。新宿主脚本沿现有发布源码范围打包，不修改旧归档，也没有进行镜像构建或导入。
