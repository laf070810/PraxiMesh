# G46：GPU 配置持久发布与进程中断恢复

日期：2026-11-01。对应 PRD R-09、R-16；[设计](rfcs/022-gpu-release-coordination.md)、[决策](adr/062-durable-gpu-configuration-publication.md)、[集中检查入口](deployment/container-gpu-worker.md#generation-configuration)。本轮只使用自有临时文件、CPU 子进程和 Docker 身份读取，未访问 GPU、加载镜像或重建现有服务。

## 实现范围

协调器内部入口现在可在原协调器/设备锁下发布 `worker.json` 与代际记录。它要求实际维护路由、完整登记且停止/不重启的原 worker、无活动或未知任务记录；原库和目标库必须同属本次暂停且无排队/运行任务与物理预约。数据库操作锁、设备表写锁和队列行锁贯穿发布；设备表锁同时阻止新设备注册插入。已删除任务的物理预约仍会拒绝切换。

部署日志持久保存非敏感的原目标上下文与文件摘要；凭证只写入私有 worker 配置。节点先持久写入发布中标记，依次原子替换两个文件，再确认活动目标，最后移除标记并确认完成。标记为空或只写到一半也会阻止配置读取。恢复只继续原 token、绑定、凭证和目标；逆序、缺标记的部分结果、未知文件与中途换库均保留现场并拒绝。

修复部署数据库 URL 与私有配置的衔接：私有配置将 `sslmode` 单独保存，密码中的特殊字符仍正确转义，原 Web/CPU URL 接口保持兼容。完整已清理任务归档复用原任务记录校验；提取前后的校验 AST 等价检查通过。新 GPU 包声明 `worker_configuration: generation-pair-v1`，旧包继续可以核验，不能因此获得新发布协议能力。

## 复现与结果

`test-results/g46-marker-before.xml` 与 `.log` 保留首次实际失败：恢复时看到完整标记直接继续，未重新同步该文件。已修正为恢复也重新执行文件 `fsync`，确认两个目标文件后再同步节点目录，随后才能记录活动目标。

最终相关回归 **615 passed、3 skipped**，结果记录在 `test-results/g46-components-final.xml` 与 `.log`。其中三项真实 PostgreSQL 专项在当前 SQLite 测试环境中跳过，不算通过。早期 48 项、206 项和完整回归、数据库定向检查分别保留在 `g46-publisher-initial`、`g46-core`、`g46-components`、`g46-database` 的日志及 XML 中；这些结果重叠，不累计为独立检查数。

配置发布测试包含 **18 次实际 SIGKILL**：首次写入和跨数据库切换各覆盖九处——持久意图、空标记、完整标记、配置临时文件、两个文件各自完成替换、活动目标确认、标记移除和最终确认。子进程退出后重用原目录及锁恢复，验证完整配置、原锁 inode、读取拒绝和临时文件清理。另检查部分写入前缀、未知状态、目标/凭证变化、暂停丢失、原节点变化、原容器身份及完整移除归档。文件、锁和进程是真实的；代理、数据库和容器状态使用明确的替身，不能证明实际 PostgreSQL 或容器生命周期成功。

原节点绑定入口另通过九项检查，见 `test-results/g46-attachment-current/result.json`：原身份保留、跨进程锁、复制协调器拒绝、四处实际 SIGKILL 及已有 worker/未知任务拒绝。69 次 Docker 调用均由受限包装器确认只执行 `info`；临时私有状态已清理。设备和初始站点元数据为合成夹具，没有启动数据库、worker 或容器。

## 尚未完成

实际 PostgreSQL 的设备插入、预约/队列行锁竞争及操作锁丢失检查已提供，当前未执行。原 worker 的实际创建、排空、停止、重启、完整启动与 GPU 代际恢复仍待接入和实测；内部配置发布不替代这些步骤。`apply` 继续拒绝 GPU 激活，正式内容与提交入口保持原门槛。

旧测试镜像恢复此前被自动审批拒绝，相关许可仍未收到；本轮未重试镜像加载、启动测试数据库或执行 [G44](acceptance-g44.md) 的真实 Web/完整 CPU 发布复验。完整 GPU、托管 CI/runner、长期部署目标和运营授权事项继续按[需求追踪](requirements.md)保留。
